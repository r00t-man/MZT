Fail2ban читает конфигурацию при старте демона и держит набор jail'ов в памяти процесса. Из-за этого правка конфигурации на уже работающем сервисе не всегда даёт ожидаемый результат: синтаксически корректный новый jail может так и не появиться среди активных. Ниже — разбор разницы между `reload` и `restart`, набор команд для диагностики и практическое правило выбора операции.

> [!NOTE]
> `fail2ban-client reload` и полный перезапуск сервиса — не взаимозаменяемые операции. Первая обновляет параметры уже загруженных в память jail'ов, вторая перечитывает конфигурацию с нуля и создаёт объекты jail'ов заново.

## Симптомы

- Новый jail добавлен в конфигурацию (в основной конфиг или в отдельный файл каталога `jail.d/*.conf`).
- `fail2ban-client -t` проходит успешно — синтаксис конфигурации корректен.
- `fail2ban-client status` показывает имя jail в списке `Jail list`.
- `fail2ban-client status <имя_jail>` не подтверждает реальной работы: банов нет, хотя в логе есть записи, явно подпадающие под фильтр.
- `fail2ban-client reload` ситуацию не меняет.

## Почему reload не поднимает новый jail

Ключевой момент — конфигурация была добавлена после того, как демон fail2ban уже был запущен и systemd-сервис находился в состоянии running. `reload` в fail2ban реализован как частичная (targeted) операция: она применяется к jail-объектам, которые уже существуют в памяти демона, и не пересобирает список jail'ов с нуля.

Поэтому ни общий `fail2ban-client reload`, ни `fail2ban-client reload <имя_jail>` не поднимают jail, которого не было на момент старта демона. Это задокументированное поведение, а не дефект конкретной установки.

## Сравнение операций

| Команда | Что происходит | Поднимает новый jail |
|---|---|---|
| `fail2ban-client reload` | перечитывает конфигурацию и обновляет параметры уже запущенных jail'ов | нет |
| `fail2ban-client reload <имя_jail>` | применяет изменения к конкретному jail, который уже существует в памяти демона | нет |
| `fail2ban-client restart` | полная переинициализация: конфигурация читается заново, список jail'ов собирается с нуля | да |
| `systemctl restart fail2ban` | полный перезапуск systemd-сервиса, конфигурация читается заново | да |

## Диагностика по шагам

1. Убедиться, что сервис запущен:

   ```bash
   systemctl status fail2ban
   ```

2. Проверить синтаксис конфигурации. Успешный результат этой проверки не означает, что jail загружен демоном, — он говорит только о корректности файлов:

   ```bash
   fail2ban-client -t
   ```

3. Посмотреть список известных демону jail'ов:

   ```bash
   fail2ban-client status
   ```

   ```text
   Status
   |- Number of jail: 2
   `- Jail list: <имя_jail_1>, <имя_jail_2>
   ```

   > [!WARNING]
   > Наличие имени в `Jail list` не доказывает, что jail реально работает. Список jail'ов и фактическое состояние backend/filter — разные вещи, и на этом этапе диагностики их легко спутать.

4. Проверить конкретный jail:

   ```bash
   fail2ban-client status <имя_jail>
   ```

   Если ожидаемой активности нет (счётчиков банов нет при подходящих записях в логе), jail, вероятнее всего, не был поднят при старте демона.

5. Попробовать частичное обновление — как правило, для нового jail оно ожидаемого эффекта не даст:

   ```bash
   fail2ban-client reload
   ```

6. Выполнить полный перезапуск:

   ```bash
   systemctl restart fail2ban
   ```

   либо

   ```bash
   fail2ban-client restart
   ```

7. Убедиться, что jail появился и работает, и при необходимости посмотреть логи сервиса:

   ```bash
   fail2ban-client status <имя_jail>
   journalctl -u fail2ban
   ```

## Правило выбора операции

> [!IMPORTANT]
> Добавлен новый jail — используйте полный перезапуск (`systemctl restart fail2ban` или `fail2ban-client restart`), а не `reload`. `reload` уместен только для изменения параметров уже работающих jail'ов.

> [!TIP]
> Порядок действий при правке конфигурации: сначала проверка синтаксиса (`fail2ban-client -t`), затем выбор операции по характеру изменения. Правка параметров существующего jail — достаточно `reload`; появление нового jail — только `restart`.

## Что требует уточнения

> [!WARNING]
> В исходных данных не указана версия fail2ban, поэтому точный формат вывода команд и поддерживаемые формы `reload`/`restart` могут отличаться — сверяйтесь с man-страницей и документацией своей версии. Случаи, когда jail не поднимается и после полного перезапуска, в этом разборе не рассматриваются: это отдельный класс причин, требующий самостоятельной диагностики.
