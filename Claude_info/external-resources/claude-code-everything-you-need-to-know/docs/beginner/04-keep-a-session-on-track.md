# Держите сессию в нужном русле

<sub>**Начинающий** · Урок 4 из 5 · около 20 минут · Требуется: [Ваше первое изменение, от запроса до коммита](03-first-change.md) · Проверено с Claude Code v2.1.292 (stable) 2026-10-15</sub>

## Цель

К концу этого урока вы сможете держать сессию в нужном русле: видеть, насколько заполнен её контекст, очищать или сжимать его, откатывать изменение и возобновлять предыдущий разговор.

## Вам понадобится

- Ваша копия практического шаблона без незакоммиченных изменений и Node.js LTS (в Codespace на вашей копии он есть). Чтобы практиковаться в одном из ваших собственных репозиториев, сохраните и копию шаблона: проверка выполняется из неё. Настройте папку `.practice/` репозитория, как описано в [уроке 1](01-install-and-look-around.md#you-need), если ещё не сделали этого. Начните с репозитория также без незакоммиченных изменений: закоммитьте их или отложите с помощью `git stash push --include-untracked`.
- Использование: небольшое.

## Идея

Всё в разговоре — ваши запросы, ответы Claude и каждый прочитанный им файл — находится в окне контекста сессии. Окно большое, но не бесконечное, и долгий, блуждающий разговор оставляет Claude меньше места для текущей важной работы ([Изучите окно контекста](https://code.claude.com/docs/en/context-window)). Пять команд помогают держать его под контролем ([Команды](https://code.claude.com/docs/en/commands)):

| Команда | Что она делает |
|---|---|
| `/context` | Показывает, насколько заполнено окно контекста, в виде цветной сетки |
| `/compact` | Суммирует разговор до текущего момента, чтобы освободить место |
| `/clear` | Начинает новый разговор с пустым контекстом |
| `/rewind` | Возвращается к более раннему запросу, восстанавливая код, разговор или и то, и другое |
| `/resume` | Продолжает предыдущий разговор |

Сжимайте, когда хотите продолжить работу над той же задачей; очищайте, когда начинаете другую. Откатывайтесь, когда изменение пошло не в ту сторону ([Контрольные точки](https://code.claude.com/docs/en/checkpointing)).

## Практический пример

1. Запустите `claude` в вашей практической копии и введите `/context`. Сетка показывает, сколько окна использовано, с разбивкой по категориям, включая ваши сообщения и любые файлы памяти, такие как `CLAUDE.md`, которые загрузились ([Изучите окно контекста](https://code.claude.com/docs/en/context-window)). В вашей практической копии пока нет `CLAUDE.md`, поэтому вы можете не увидеть файлов памяти; [урок 5](05-project-memory.md) добавит один.
2. Немного заполните его:

   ```text
   Explain how src/check-links.js decides that a link is broken.
   ```

   Снова выполните `/context`: часть с сообщениями выросла.
3. Сожмите, указав Claude, что сохранить:

   ```text
   /compact keep what we learned about check-links.js
   ```

   Разговор заменяется сводкой: в `/context` часть с сообщениями уменьшается, а свободное место растёт. После одного короткого вопроса суммировать почти нечего, поэтому изменение небольшое; сжатие окупается, когда разговор становится длинным.
4. Сделайте изменение, которое нужно отменить. Rewind не может отменить изменения, которые Claude вносит, выполняя команды (см. [Будьте внимательны](#watch-out)), поэтому в запросе попросите использовать его инструмент редактирования файлов. Одобрите правку, если Claude спросит:

   ```text
   In src/cli.js, change the success message to "All relative links are fine." Use your file editing tool, not a shell command.
   ```

   Во втором терминале в той же папке сохраните то, что видит git:

   ```bash
   git status --porcelain > .practice/b-4-before-rewind.txt
   ```

   Файл содержит `src/cli.js`.
5. Откатитесь. Введите `/rewind` или нажмите `Esc` дважды при пустом запросе. Выберите запрос из шага 4 и выберите **Restore code and conversation**. Если меню предлагает только **Restore conversation**, варианты суммирования и **Never mind**, Claude изменил файл командой, что rewind не может отменить: выберите **Never mind**, нажмите `Esc`, чтобы закрыть меню ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode)), выполните `git restore src/cli.js` во втором терминале и повторите шаг 4.

   После восстановления кода сохраните то, что видит git, во втором терминале:

   ```bash
   git status --porcelain > .practice/b-4-after-rewind.txt
   ```

   Этот файл пуст: правка исчезла. Если рядом с разговором открыта панель diff, она всё ещё может показывать правку: Claude Code обновляет панель каждый раз, когда Claude редактирует файл или выполняет команду оболочки ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode#diff-panel)). Пустой файл показывает, что видит git.
6. Rewind вернул ваш запрос из шага 4 в поле ввода, поэтому всё, что вы теперь напечатаете, добавится к нему. Быстро нажмите `Esc` дважды, чтобы очистить его. Затем введите `/clear`. Разговор начинается заново с пустым контекстом, а старый остаётся доступным.
7. Введите `/exit`, затем снова откройте самый последний разговор в этой папке ([Управление сессиями](https://code.claude.com/docs/en/sessions)):

   ```bash
   claude --continue
   ```

   Если откроется пустой разговор из шага 6, выполните `/resume` и выберите более ранний. Внутри сессии `/resume` без аргумента открывает список предыдущих разговоров. Выбранный разговор может всё ещё показывать отменённую правку, потому что он был сохранён до отката. Ваши файлы остаются такими, какими их оставил откат (`git status --porcelain` ничего не выводит), поэтому не просите Claude снова внести эту правку. Если Claude предложит повторить отменённую правку, скажите нет.

## Ваша очередь

Повторите пример в своей практической копии или собственном репозитории:

1. Выполните `/context`, задайте один вопрос о коде и снова выполните `/context`.
2. Выполните `/compact` с предложением о том, что сохранить.
3. Попросите внести небольшую правку в один файл, закончив запрос словами "Use your file editing tool, not a shell command.", и одобрите её, если Claude спросит. Сохраните `git status --porcelain > .practice/b-4-before-rewind.txt`.
4. Откатите этот запрос с помощью **Restore code and conversation** и сохраните `git status --porcelain > .practice/b-4-after-rewind.txt`.
5. Быстро нажмите `Esc` дважды, чтобы очистить восстановленный запрос, затем выполните `/clear`, затем `/exit`, затем `claude --continue`.

## Проверка

Вы закончили, когда все следующие условия истинны:

- [ ] `.practice/b-4-before-rewind.txt` содержит файл, который изменил Claude: `cat .practice/b-4-before-rewind.txt`.
- [ ] `.practice/b-4-after-rewind.txt` не содержит файлов: `cat .practice/b-4-after-rewind.txt` ничего не выводит.
- [ ] Самопроверка (не тестируется): вы можете сказать, когда использовать `/compact`, а когда `/clear`.

Выполните `npm run check -- b-4` в своей практической копии. В собственном репозитории вместо этого выполните `npm run check -- b-4 --dir <your repo>` из практической копии.

Если первый файл пуст, вы сохранили его до внесения правки; внесите правку снова, сохраните файл после неё, затем снова откатитесь. Если второй файл всё ещё содержит файл, который изменил Claude, откатите этот запрос с опцией, восстанавливающей код, затем снова сохраните второй файл. Если меню больше не содержит этот запрос (после **Restore conversation**) или не предлагает опцию, восстанавливающую код (Claude использовал команду), выполните `git restore <file>` и вместо этого повторите шаги 3 и 4 раздела «Ваша очередь». Файлы, которые вы изменили до урока, также остаются в списке, потому что rewind не может их отменить: закоммитьте их или отложите с помощью `git stash push --include-untracked`, затем снова сохраните второй файл.

## Будьте внимательны

- Rewind отменяет только правки, которые Claude внёс своими инструментами редактирования файлов. Изменения, сделанные выполненными им командами, например удаление файла с помощью `rm`, остаются ([Контрольные точки](https://code.claude.com/docs/en/checkpointing#bash-command-changes-not-tracked)); коммитьте свою работу, чтобы git мог её вернуть.
