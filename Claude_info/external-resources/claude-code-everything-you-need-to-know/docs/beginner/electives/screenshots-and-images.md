# Дайте Claude скриншот

<sub>**Начинающий** · Электив · около 15 минут · Требуется: [Ваше первое изменение, от запроса до коммита](../03-first-change.md) · Проверено с Claude Code v2.1.292 (stable) 2026-10-15</sub>

## Цель

К концу этого Электива вы сможете добавить скриншот или изображение в разговор и получить изменение на основе того, что на нем показано.

## Вам понадобится

- Ваша копия практического шаблона без незакоммиченных изменений и инструмент для создания скриншотов в вашей системе.
- Использование: небольшое.

> [!NOTE]
> В Codespace Claude Code работает внутри codespace, а не на вашем компьютере ([Контейнеры разработки](https://code.claude.com/docs/en/devcontainer)), поэтому передавайте скриншоты как файлы туда. Сохраните каждый скриншот на своем компьютере, переименуйте его в имя, используемое на этой странице (`shot.png`, затем `test-summary.png`), и перетащите его из файлового менеджера вашего компьютера в папку `.practice` в проводнике codespace ([GitHub Codespaces](https://code.visualstudio.com/docs/remote/codespaces#_known-limitations-and-adaptations)). Там, где в Рабочем примере сказано вставить, вместо этого спросите с указанием пути, например: `Посмотри на это изображение: .practice/shot.png`. В разделе Ваша очередь пропустите строку с `mv`.

## Идея

Некоторые вещи быстрее показать, чем описать: ошибку на экране, макет, диаграмму. Claude Code читает изображения, и вы можете добавить одно в разговор тремя способами ([Общие рабочие процессы](https://code.claude.com/docs/en/common-workflows#work-with-images)):

- перетащите изображение в окно Claude Code;
- скопируйте изображение и вставьте его с помощью `Ctrl+V` (`Cmd+V` также работает в iTerm2; `Alt+V` в Windows и WSL) ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode#general-controls));
- укажите его путь в вашем запросе, например: "Посмотри на это изображение: /path/to/shot.png".

## Рабочий пример

1. В вашей практической копии запустите проверку ссылок на образцах:

   ```bash
   npm run linkcheck -- samples
   ```

   Он выводит неработающую ссылку в `guide.md`, затем `1 broken link(s)`.
2. Сделайте скриншот этого вывода и скопируйте его в буфер обмена. На Mac нажмите `Ctrl` вместе с обычными клавишами, например `Ctrl+Shift+Cmd+4`: без этого macOS сохраняет скриншот как файл, по умолчанию на рабочем столе ([Сделать скриншот на Mac](https://support.apple.com/en-us/102646)).
3. Запустите `claude` и вставьте изображение. В поле запроса появится чип `[Image #1]` ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode#general-controls)). Если чип не появился, вместо этого перетащите файл скриншота в окно Claude Code или укажите его путь, как в разделе Ваша очередь. Затем спросите:

   ```text
   Это вывод проверки ссылок. Измени последнюю строку так, чтобы она также сообщала, сколько файлов Markdown было проверено, например: "1 broken link(s) in 2 files".
   ```

4. Одобрите правку, если Claude попросит. Затем во втором терминале в той же папке снова запустите `npm run linkcheck -- samples`. Последняя строка теперь указывает количество файлов.
5. Во втором терминале выполните `git diff`, чтобы увидеть изменение. Затем отложите изменение из примера, чтобы раздел Ваша очередь начался с чистого состояния:

   ```bash
   git stash push --include-untracked -m b-images-example
   ```

   `git status` затем покажет `nothing to commit, working tree clean`.

## Ваша очередь

1. Во втором терминале запустите `npm test` и сделайте скриншот конца его вывода: последние несколько названий тестов и сводку под ними. Сохраните его как файл, затем переместите его в папку `.practice/` вашей практической копии. Git игнорирует эту папку, поэтому изображение никогда не появится как изменение:

   ```bash
   mv "<ваш файл скриншота>" .practice/test-summary.png
   ```

   **WSL:** Windows сохраняет файл на своем собственном диске, к которому WSL обращается через `/mnt/c` ([Работа между файловыми системами](https://learn.microsoft.com/en-us/windows/wsl/filesystems)): `C:\Users\<имя пользователя>\shot.png` — это `/mnt/c/Users/<имя пользователя>/shot.png`.
2. В Claude Code (запустите `claude`, если он не запущен) спросите о нем по пути: `Посмотри на это изображение: .practice/test-summary.png. Что означает каждая строка этой сводки?`
3. Попросите небольшое изменение на основе изображения, например, более понятное имя для одного из показанных тестов, и одобрите правку, если Claude попросит. Проверьте это с помощью `git diff` во втором терминале.

## Проверка

В этом Элективе нет `npm run check`: отметьте каждый пункт самостоятельно. Вы закончили, когда все следующие условия истинны:

- [ ] `git diff` показывает изменение, которое вы запросили на основе изображения.
- [ ] Самопроверка (не тестируется): вы добавили одно изображение вставкой или перетаскиванием, а другое — по пути (в Codespace оба по пути).

Когда закончите, отложите свое изменение, чтобы следующий урок начался с чистого состояния: `git stash push --include-untracked -m b-images`. `git status` затем покажет `nothing to commit, working tree clean`.

## Будьте внимательны

- Изображение отправляется Claude вместе с вашим запросом. Вырезайте все личное, например токены, адреса электронной почты или данные клиентов, прежде чем вставлять его.
