# Выбирайте, кто что одобряет: режимы разрешений и plan mode

<sub>**Начинающий** · Урок 2 из 5 · около 20 минут · Требуется: [Установка, вход и осмотр](01-install-and-look-around.md) · Проверено на Claude Code v2.1.292 (stable) 2026-10-15</sub>

## Цель

К концу этого урока вы сможете выбирать режим разрешений для задачи, переключать режимы во время сеанса и использовать plan mode для одобрения плана перед тем, как Claude изменит ваши файлы.

## Вам понадобится

- Ваша копия практического шаблона, склонированная, без незакоммиченных изменений, и Node.js LTS для проверок (Codespace на вашей копии имеет и то, и другое). Чтобы практиковаться в одном из ваших собственных репозиториев, сначала закоммитьте или спрячьте там свою работу, чтобы там тоже не было незакоммиченных изменений, и сохраните копию шаблона: проверка выполняется из неё. Настройте папку `.practice/` репозитория, как описано в [уроке 1](01-install-and-look-around.md#you-need), если ещё не сделали этого.
- Использование: небольшое.

> [!NOTE]
> На нативном Windows выполняйте команды в PowerShell и используйте строки, помеченные **Windows**, где они отличаются. Если `Shift+Tab` ничего не делает, нажмите `Alt+M` вместо этого ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode)).

## Идея

[Режим разрешений](https://code.claude.com/docs/en/permission-modes) определяет, какие действия Claude может выполнять без предварительного запроса. Вы переключаете режимы с помощью `Shift+Tab`, и строка состояния под подсказкой всегда показывает действующий режим.

Сейчас важны четыре режима:

| Строка состояния показывает | Режим | Claude делает это без запроса |
|---|---|---|
| `⏸ manual mode on` | Manual | Только чтение |
| `⏵⏵ accept edits on` | Accept edits | Чтение, редактирование файлов, выполнение обычных файловых команд |
| `⏸ plan mode on` | Plan | Чтение, плюс команды, которые фоновая проверка безопасности одобряет при доступном auto mode, затем пишет план. Не может редактировать ваши файлы, пока вы не одобрите план |
| `⏵⏵ auto mode on` | Auto | Всё, с фоновыми проверками безопасности |

Manual подходит для чувствительной работы и незнакомого кода, когда вы хотите самостоятельно просматривать каждое действие. Auto подходит для длительных задач, избавляя вас от одобрения каждого шага.

Plan mode — это привычка, которую стоит выработать в первую очередь: вы видите всё изменение в виде плана до того, как Claude отредактирует какие-либо ваши файлы.

## Разобранный пример

1. Запустите `claude` в вашей практической копии и посмотрите на строку состояния. Новый сеанс обычно начинается в auto mode.
2. Нажимайте `Shift+Tab`, пока строка состояния не покажет `⏸ plan mode on`. Из auto первое нажатие даёт Manual, затем Accept edits, затем Plan.
3. Запросите изменение:

   ```text
   Make parseConfig in src/config.js reject an empty file with a clear error message, and add a test for it.
   ```

4. Claude читает файлы и может запускать команды для исследования, но не редактирует ваши файлы. Если ему сначала нужно ваше решение, он задаёт [вопрос с несколькими вариантами ответа](https://code.claude.com/docs/en/tools-reference#askuserquestion-tool-behavior): выберите вариант или введите свой ответ, и он продолжит планирование. Затем он показывает план и спрашивает, как действовать, с тремя вариантами:
   - **Yes, and use auto mode** (читается **Yes, auto-accept edits**, если auto mode вам недоступен)
   - **Yes, manually approve edits**
   - Текстовое поле с надписью **Tell Claude what to change** (в [документации](https://code.claude.com/docs/en/permission-modes#review-and-approve-a-plan) этот вариант называется **No, keep planning**)

   Первый вариант выделен при открытии меню. Пока вы не выберете, сеанс остаётся в plan mode.
5. Отправьте план обратно один раз, даже если он уже выглядит правильным, чтобы попрактиковаться. Используйте `Down arrow`, чтобы переместить выделение на **Tell Claude what to change**, введите это исправление в этой строке и нажмите `Enter`:

   ```text
   Keep the change to src/config.js and test/config.test.js. Don't add new files.
   ```

   Отправьте с помощью `Enter`, а не `Shift+Tab`: в этом меню `Shift+Tab` одобряет план ([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). Claude пересматривает план и снова показывает меню. Если вы нажмёте `Enter` до ввода текста, Claude Code покажет `User rejected Claude's plan:` и сеанс останется в plan mode, ожидая вас: введите исправление в подсказке.
6. Когда пересмотренный план выглядит правильным, оставьте его на экране и откройте другой терминал в той же папке. Сохраните то, что видит git, и файлы, которые план говорит, что изменит, по одному пути на строку, записанные так, как их показывает `git status` (относительно корня репозитория, с прямыми слэшами):

   ```bash
   git status --porcelain > .practice/b-2-before.txt
   printf '%s\n' src/config.js test/config.test.js > .practice/b-2-plan.txt
   ```

   **Windows:** `'src/config.js','test/config.test.js' | Set-Content .practice/b-2-plan.txt` заменяет строку с `printf`.
7. Вернитесь в Claude Code, используйте `Down arrow`, чтобы переместить выделение на **Yes, manually approve edits**, и нажмите `Enter`. Нажатие `Enter` на выделенном первом варианте позволит Claude редактировать без запроса. Сеанс выходит из plan mode в Manual mode, поэтому Claude спрашивает перед каждым редактированием и перед большинством команд оболочки, таких как запуск тестов.

   Читайте каждый запрос и отвечайте просто **Yes**: другие варианты Yes останавливают повторные запросы Claude для такого типа действий или переключают сеанс в Accept edits или auto mode ([Настройка разрешений](https://code.claude.com/docs/en/permissions#permission-system)). Если команда делает больше, чем нужно по плану, выберите **No** и скажите Claude, что делать вместо этого. Когда Claude закончит, сохраните то, что видит git сейчас, в другом терминале:

   ```bash
   git status --porcelain > .practice/b-2-after.txt
   ```

8. Отложите изменение из примера, чтобы раздел «Ваша очередь» начался с чистого состояния. Git игнорирует `.practice/`, поэтому ваши снимки сохранятся:

   ```bash
   git stash push --include-untracked -m b-2-example
   ```

## Ваша очередь

Повторите пример в вашей практической копии или вашем собственном репозитории с небольшим собственным изменением:

1. Переключитесь в plan mode с помощью `Shift+Tab`, пока строка состояния не покажет `⏸ plan mode on`.
2. Запросите изменение и ответьте на любой вопрос Claude.
3. Отправьте план обратно один раз: введите одно исправление в **Tell Claude what to change** и нажмите `Enter`.
4. Пока финальный план на экране, выполните команды шага 6 в другом терминале со списком файлов вашего плана.
5. Одобрите с помощью **Yes, manually approve edits**, читайте и одобряйте каждое редактирование и команду, как в шаге 7, затем сохраните `git status --porcelain > .practice/b-2-after.txt`.

Остановитесь до коммита. Следующий урок начинается с чистого дерева и доводит новое изменение до коммита.

## Проверка

Вы закончили, когда все следующие условия верны:

- [ ] `.practice/b-2-before.txt`, сохранённый, пока план был на экране, не содержит файлов. `cat .practice/b-2-before.txt` ничего не выводит.
- [ ] Каждый путь в `.practice/b-2-after.txt` присутствует в `.practice/b-2-plan.txt`.
- [ ] Самопроверка (не тестируется): скажите одним предложением, когда вы выбрали бы Manual вместо Auto.

В другом терминале выполните `npm run check -- b-2` в вашей практической копии. В вашем собственном репозитории выполните `npm run check -- b-2 --dir <your repo>` из вашей практической копии.

Если `.practice/b-2-before.txt` содержит файлы, либо дерево не было чистым, когда началась «Ваша очередь» (файлы из разобранного примера означают, что шаг 8 был пропущен; в вашем собственном репозитории это ваша незакоммиченная работа), либо Claude записал файл до вашего одобрения: проверьте, что строка состояния показывала `⏸ plan mode on`, когда вы отправили подсказку, и поищите в сеансе команду Claude, которая записала файл. В любом случае отложите изменения с помощью `git stash push --include-untracked` (или закоммитьте свою работу), затем повторите «Вашу очередь» с шага 1, чтобы снимки сохранились снова. Если изменённый путь отсутствует в `.practice/b-2-plan.txt`, проверьте, что файл плана записывает его так же, как `git status`, затем сравните одобренный план с тем, что изменил Claude.

## Дальнейшие шаги

- Введите `/plan <your task>`, чтобы войти в plan mode и начать задачу за один шаг ([Команды](https://code.claude.com/docs/en/commands)).
- [Анализируйте перед редактированием с plan mode](https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode): более глубокое планирование, включая редактирование плана перед одобрением.
