# Начинающий уровень: итоговое задание — исправьте зарегистрированный баг, от плана до коммита

<sub>**Начинающий** · Итоговое задание · 30–60 минут · Требуется: пять [уроков для начинающих](README.md) или их навыки · Проверено на Claude Code v2.1.292 (stable) 2026-10-15</sub>

Это задание объединяет весь уровень для начинающих. В отличие от уроков, здесь нет готового примера: шаги говорят, что делать, а подсказки вы выбираете сами. [Выход с уровня для начинающих](README.md#by-the-end-of-this-level-you-can) — это список того, что вы сможете делать к концу уровня. Проверка читает файлы и коммит, оставленный этим заданием, а остальные пункты выхода вы отмечаете сами в разделе [Что проверка не видит](#what-the-check-cant-see). Когда и то, и другое выполнено, вы продемонстрировали выход с уровня для начинающих, независимо от того, проходили ли вы уроки.

## Вам понадобится

- Ваша копия практического шаблона без незакоммиченных изменений и Node.js LTS (в Codespace на вашей копии он есть). Если `git status --porcelain` выводит файлы, закоммитьте их или временно отложите с помощью `git stash push --include-untracked`. Итоговое задание выполняется только в шаблоне.
- Если вы пропустили уроки: создайте папку `.practice/` в своей копии (`mkdir -p .practice`; **Windows:** `New-Item -ItemType Directory -Force .practice`). Шаблон уже настроен так, чтобы git игнорировал её.
- Закоммиченный `CLAUDE.md` в вашей копии, в котором указана команда тестирования `npm test`: `git show HEAD:CLAUDE.md` покажет его. Урок 5 даёт такой файл; если в вашем не указана `npm test`, добавьте её.
- Если вы пропустили урок 5 или выполняли его только в своём репозитории: запустите `claude` в своей копии и выполните `/init`. В новом `CLAUDE.md` удалите всё, что говорится о файлах самого курса (`checks/`, `learn/`, `capstone/` и `.github/`) и о командах `npm run check`, `npm run learn` и `npm run test:checks`, включая любое правило, запрещающее держать вашу работу вне `main`: это правило для репозитория шаблона, а не для вашей копии. Убедитесь, что в файле указана `npm test`.
- Закоммитьте любое изменение `CLAUDE.md` отдельно перед началом (`git add CLAUDE.md`, затем `git commit -m "Add CLAUDE.md"`): коммит с исправлением может менять только файлы, указанные в плане.
- Использование: умеренное.

> [!NOTE]
> На нативном Windows выполняйте все команды в PowerShell. Команда без строки **Windows** работает там как написано; если после команды идёт строка **Windows**, используйте её вместо основной. Если `Shift+Tab` не срабатывает, нажмите `Alt+M` ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode)).

## Задание

Коллега зарегистрировал баг-репорт в `capstone/beginner-bug.md` в вашей практической копии: когда `linkcheck.json` указывает несуществующую папку, инструмент сообщает, что все ссылки разрешаются, и завершается с кодом 0.

Чтобы воспроизвести баг вручную, создайте новую папку вне практической копии и сохраните в ней `{ "files": ["docs"] }` как `linkcheck.json`. Затем выполните `npm run linkcheck -- <та папка>` в своей копии: пока баг не исправлен, будет выведено `All relative links resolve.` Не кладите `linkcheck.json` в свою копию, потому что проверка посчитает это изменением. **Windows:** сохраните файл командой `'{ "files": ["docs"] }' | Set-Content <та папка>\linkcheck.json`, а не `>`. В Windows PowerShell 5.1 `>` записывает UTF-16 ([about_Character_Encoding](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_character_encoding?view=powershell-5.1)), который инструмент отклоняет как невалидный JSON с кодом выхода 2, даже до исправления.

Исправьте баг так, как учили уроки для начинающих:

1. Сохраните вывод `claude --version` в `.practice/version.txt`.
2. Начните сессию и переключитесь в plan mode до первого промпта. Затем попросите Claude прочитать баг-репорт и спланировать исправление. Исправление затрагивает два исходных файла и как минимум один тестовый файл. Попросите план, который сначала добавляет тест и запускает его до изменения кода, чтобы вы увидели его падение ([Best practices](https://code.claude.com/docs/en/best-practices#provide-specific-context-in-your-prompts): "напишите падающий тест, воспроизводящий проблему, затем исправьте её").
3. Пока финальный план на экране, откройте другой терминал в той же папке. Сохраните `git status --porcelain` в `.practice/capstone-before.txt`. Сохраните файлы, которые план будет менять, включая все тестовые файлы, в `.practice/capstone-plan.txt`: по одному пути на строку, относительно корня репозитория, с прямыми слэшами, например `src/cli.js`.
4. Одобрите план. Наблюдайте, как новый тест падает, а затем проходит после исправления. Чтобы прочитать вывод теста, а не только сводку Claude, нажмите `Ctrl+O`, как в [уроке 3](03-first-change.md#worked-example), и `Esc`, чтобы вернуться ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode#general-controls)).
5. Просмотрите весь diff, включая тестовый файл, как в [уроке 3](03-first-change.md#worked-example). Список на панели diff не показывает тестовые файлы, пока вы не нажмёте на строку, которая их подсчитывает ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode#diff-panel)). `git diff` не показывает новый файл, пока вы не выполните `git add -N <файл>` ([git add](https://git-scm.com/docs/git-add#Documentation/git-add.txt--N)). Попросите хотя бы одно исправление, которое остаётся в пределах файлов, указанных в плане, и убедитесь, что `npm test` проходит.
6. Закоммитьте исправление и его тест вместе, затем сохраните коммит командой `git rev-parse HEAD > .practice/capstone-commit.txt`. Проверка читает только этот коммит, поэтому если вы позже измените его, сохраните снова.

Поддерживайте сессию в рабочем состоянии: проверяйте `/context`, при необходимости сжимайте или перематывайте.

## Проверка

Вы закончили, когда все следующие условия истинны:

- [ ] `.practice/version.txt` содержит вывод `claude --version`.
- [ ] `.practice/capstone-before.txt`, сохранённый, пока план был на экране, не содержит изменённых файлов.
- [ ] Коммит в `.practice/capstone-commit.txt` меняет только файлы, перечисленные в `.practice/capstone-plan.txt`, включая тестовый файл.
- [ ] Баг исправлен: с `linkcheck.json` из баг-репорта в папке вне вашей копии `npm run linkcheck -- <та папка>` завершается с кодом 2.
- [ ] `npm test` проходит.
- [ ] Закоммиченный `CLAUDE.md` указывает команду тестирования `npm test`.
- [ ] `git status --porcelain` ничего не выводит.

Выполните `npm run check -- b-capstone` в своей практической копии. Каждый непройденный пункт выведет, что исправить.

## Что проверка не видит

Проверка не смотрит на эти части выхода с уровня для начинающих. Отметьте их сами, честно:

- [ ] Я могу определить, какая модель и аккаунт используются в сессии, с помощью `/status`.
- [ ] Я могу переключать режимы разрешений с помощью `Shift+Tab` и сказать, какой нужен для задачи.
- [ ] Я прочитал весь diff перед коммитом и попросил Claude внести хотя бы одно исправление.
- [ ] Я могу поддерживать сессию в рабочем состоянии с помощью `/context`, `/clear`, `/compact`, `/rewind` и `/resume`.
- [ ] Я видел, как новая сессия следует правилу из CLAUDE.md, которое я не повторял в промпте. Если вы пропустили урок 5, его [Worked example](05-project-memory.md#worked-example) покажет, как это сделать.

Когда все чекбоксы на этой странице отмечены, вы готовы к [среднему уровню](../intermediate/README.md). Его список "ready if" — это выход с уровня для начинающих.

Если этот уровень помог, поставьте звезду — это поможет другим разработчикам найти руководство.
