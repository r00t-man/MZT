# Запуск и сохранение динамического рабочего процесса

<sub>**Продвинутый** · Урок 3 из 7 · около 20 минут, плюс время выполнения · Требуется: [Выбор паттерна оркестрации](02-orchestration-patterns.md) · Проверено на Claude Code v2.1.292 (stable) 2026-10-15</sub>

## Цель

К концу этого урока вы сможете попросить Claude написать динамический рабочий процесс для задачи, которая распределяется по множеству файлов, сохранить его компактным и сохранить как команду, которая принимает входные данные из `args`.

## Что вам понадобится

- Один из ваших собственных репозиториев, в котором есть как минимум две папки, каждая из которых содержит комментарий `TODO` или `FIXME`, который всё ещё актуален для кода: `git grep -n -E 'TODO|FIXME'` выводит их список. Если в вашем репозитории таких нет, используйте локальный клон проекта, в котором они есть; вы не будете отправлять в него изменения. Выполняйте проверку из вашей копии практического шаблона с Node.js LTS. Настройте папку `.practice/` репозитория, как описано в [Уроке 1 для начинающих](../beginner/01-install-and-look-around.md#you-need), если ещё не сделали этого.
- Использование: интенсивное. Каждый запуск порождает несколько субагентов, а `/deep-research` также ищет в интернете ([Запуск встроенного рабочего процесса](https://code.claude.com/docs/en/workflows#run-a-bundled-workflow)). Дешёвый вариант: пропустите шаг 3, ограничьте каждый запуск одной небольшой папкой и запускайте Claude Code с `--model sonnet`, как показано в шаге 1.

> [!NOTE]
> На тарифе Pro динамические рабочие процессы отключены, пока вы не включите их в строке **Dynamic workflows** в `/config`, а руководство по размеру по умолчанию — `small` ([Оркестрация субагентов в масштабе с помощью динамических рабочих процессов](https://code.claude.com/docs/en/workflows), [Установка руководства по размеру](https://code.claude.com/docs/en/workflows#set-a-size-guideline)).

## Идея

Динамический рабочий процесс — это JavaScript-скрипт, который Claude пишет для вашей задачи. Среда выполнения запускает его в фоновом режиме, пока ваша сессия остаётся отзывчивой ([Оркестрация субагентов в масштабе с помощью динамических рабочих процессов](https://code.claude.com/docs/en/workflows)). Скрипт запускает субагентов и хранит их результаты в собственных переменных, так что до вашего разговора доходит только итоговый ответ: план хранит скрипт, а не Claude ([хранит план](02-orchestration-patterns.md#the-idea) ([Когда использовать рабочий процесс](https://code.claude.com/docs/en/workflows#when-to-use-a-workflow)).

Поскольку план — это код, вы можете прочитать его до запуска, независимые агенты могут проверять выводы друг друга до того, как о них будет сообщено, а удачный запуск можно сохранить как команду `/<name>`, которая каждый раз может принимать новые входные данные из `args` ([Когда использовать рабочий процесс](https://code.claude.com/docs/en/workflows#when-to-use-a-workflow), [Передача входных данных в сохранённый рабочий процесс](https://code.claude.com/docs/en/workflows#pass-input-to-a-saved-workflow)).

Руководство по размеру подсказывает Claude, на сколько агентов ориентироваться при написании скрипта. Это совет, а не жёсткое ограничение ([Установка руководства по размеру](https://code.claude.com/docs/en/workflows#set-a-size-guideline)).

## Практический пример

1. В корне вашего репозитория запустите Claude Code в ручном режиме:

   ```bash
   claude --permission-mode manual
   ```

   Для дешёвого варианта запустите его на Sonnet:

   ```bash
   claude --permission-mode manual --model sonnet
   ```

   В строке состояния отображается `⏸ manual mode on` ([Переключение режимов разрешений](https://code.claude.com/docs/en/permission-modes#switch-permission-modes)). В ручном режиме Claude Code спрашивает перед каждым запуском рабочего процесса, если вы не указали не спрашивать снова для этого рабочего процесса в данном проекте, поэтому вы видите каждый план до его запуска ([Одобрение плана перед запуском](https://code.claude.com/docs/en/workflows#approve-the-plan-before-it-runs)).

   Если ничто другое не назначает модель, агенты рабочего процесса работают на модели вашей сессии ([Стоимость](https://code.claude.com/docs/en/workflows#cost)). `--model` устанавливает её только для этой сессии, тогда как `/model` также сохранила бы её как модель по умолчанию ([Флаги CLI](https://code.claude.com/docs/en/cli-reference#cli-flags), [Команды](https://code.claude.com/docs/en/commands#all-commands)).
2. Установите руководство по размеру:

   ```text
   /config workflowSizeGuideline=small
   ```

   `small` просит Claude использовать минимальное количество агентов; в документации предлагается использовать его, «когда вы хотите ограничить расходы рабочего процесса». Claude Code сохраняет этот выбор в `~/.claude.json`, а не в репозитории, и он применяется со следующего запроса ([Все настройки](https://code.claude.com/docs/en/settings-reference#workflowsizeguideline), [Установка руководства по размеру](https://code.claude.com/docs/en/workflows#set-a-size-guideline)).
3. Пропустите этот шаг в дешёвом варианте. Запустите встроенный исследовательский рабочий процесс ([Запуск встроенного рабочего процесса](https://code.claude.com/docs/en/workflows#run-a-bundled-workflow)). Ему нужен инструмент WebSearch, который Amazon Bedrock не предоставляет ([Поведение инструмента WebSearch](https://code.claude.com/docs/en/tools-reference#websearch-tool-behavior)):

   ```text
   /deep-research What changed in the Node.js permission model between v20 and v22?
   ```

   Claude Code перечисляет запланированные этапы и спрашивает, запускать ли его. Поскольку вы запустили рабочий процесс по имени, он также предлагает **Yes, and don't ask again for `<name>` in `<path>`** ([Одобрение плана перед запуском](https://code.claude.com/docs/en/workflows#approve-the-plan-before-it-runs)). Выберите **Yes, run it**. Запуск выполняется в фоновом режиме. Его агенты используют ваши правила разрешений, поэтому в ручном режиме поиск или загрузка страницы может остановиться для вашего одобрения, и запуск будет ждать, пока вы не ответите ([Поведение и ограничения](https://code.claude.com/docs/en/workflows#behavior-and-limits)). По завершении отчёт появится в вашей сессии со ссылками на источники. Дождитесь его, прежде чем продолжить.
4. Запросите собственный рабочий процесс. Замените `<folder>` на небольшую папку вашего репозитория:

   ```text
   use a workflow to audit every file under <folder> for errors that are caught and then ignored, and adversarially verify each finding before reporting it
   ```

   Просьба о «рабочем процессе» своими словами говорит Claude написать его для этой задачи ([Запрос рабочего процесса в промпте](https://code.claude.com/docs/en/workflows#ask-for-a-workflow-in-your-prompt)). Затем Claude Code спрашивает, запускать ли его, перечисляя запланированные этапы, с вариантами **Yes, run it**, **View raw script** и **No**. Скрипт, написанный Claude для этой задачи, не получает опции «не спрашивать снова». Выберите **View raw script**, чтобы сначала прочитать его, или нажмите `Ctrl+G`, чтобы открыть его в редакторе ([Одобрение плана перед запуском](https://code.claude.com/docs/en/workflows#approve-the-plan-before-it-runs)). Он имеет структуру примера из документации, хотя ваш будет отличаться:

   ```javascript
   export const meta = {
     name: 'audit-routes',
     description: 'Audit every route handler for missing auth checks',
   }

   const found = await agent('List every .ts file under src/routes/.', {
     schema: { type: 'object', required: ['files'], properties: { files: { type: 'array', items: { type: 'string' } } } },
   })

   const audits = await pipeline(found.files, file =>
     agent(`Audit ${file} for missing authentication checks.`, { label: file }),
   )

   return audits.filter(Boolean)
   ```

   `agent()` запускает одного субагента, `pipeline()` запускает по одному на каждый элемент списка, а `parallel()` запускает набор агентов одновременно ([Как выглядит сохранённый скрипт](https://code.claude.com/docs/en/workflows#what-the-saved-script-looks-like)). Затем выберите **Yes, run it**.
5. Пока он работает, выполните `/workflows` и выберите ваш запуск аудита; если в сессии только один запуск, он откроется напрямую. Представление прогресса показывает каждый этап с количеством агентов. `↑` и `↓` выбирают, `Enter` открывает этап, а затем агента (его промпт, последние вызовы инструментов и результат), `Esc` возвращает назад, а `p` приостанавливает или возобновляет запуск ([Наблюдение за запуском](https://code.claude.com/docs/en/workflows#watch-the-run)). Однострочная сводка прогресса также отображается на панели задач под полем ввода ([Запуск встроенного рабочего процесса](https://code.claude.com/docs/en/workflows#run-a-bundled-workflow)).
6. Когда запуск завершится и его результаты появятся в вашей сессии, выполните `/workflows`, выберите ваш запуск аудита, а не `/deep-research`, и нажмите `s`. В диалоге сохранения `Tab` переключает между `.claude/workflows/` в вашем проекте, доступной всем, кто клонирует репозиторий после коммита, и `~/.claude/workflows/`, доступной во всех проектах, но только вам. Убедитесь, что выбрана `.claude/workflows/` в вашем проекте, нажав `Tab`, если это не так, затем нажмите `Enter` ([Сохранение рабочего процесса для повторного использования](https://code.claude.com/docs/en/workflows#save-the-workflow-for-reuse)). Claude Code записывает скрипт как файл `.js` в ближайшую существующую папку `.claude/workflows/` между вашим рабочим каталогом и корнем репозитория или в `.claude/workflows/` в корне, если её ещё нет. Со следующей сессии рабочий процесс запускается как команда `/<name>`, отображаемая в автодополнении `/` рядом с `/deep-research` ([Встроенные рабочие процессы](https://code.claude.com/docs/en/workflows#bundled-workflows)).

## Ваша очередь

**Задание:** создайте рабочий процесс, который находит все комментарии `TODO` и `FIXME` в указанной вами папке, проверяет, актуален ли каждый из них для текущего кода, и сообщает только о тех, которые актуальны. Сделайте его компактным: пусть его агенты проверяют комментарии несколькими партиями, а не по одному агенту на комментарий. Выберите две папки, в каждой из которых есть хотя бы один актуальный `TODO` или `FIXME`: отчёт, который ничего не находит, не содержит `path:line` и не проходит проверку.

**Критерии приёмки:**

- Он сохранён в `.claude/workflows/`, закоммичен и запускается по имени. Его первым оператором остаётся `export const meta`, простой литерал объекта с `name` и `description`: переменная, вызов функции или spread там убирают `/<name>` из автодополнения `/` ([Редактирование сохранённого скрипта](https://code.claude.com/docs/en/workflows#edit-a-saved-script)).
- Он читает папку из `args`, поэтому `Run /<name> on <folder>` работает с любой папкой без редактирования скрипта.
- Каждый сообщаемый элемент начинается со строки `TODO` или `FIXME` в формате `path:line` от корня репозитория, затем в одной строке объясняется, почему он всё ещё актуален, без ссылок на другие `path:line`. Элементы, которые больше не актуальны, опускаются.
- Запуск на одной небольшой папке не показывает предупреждение `Large workflow` на панели задач. При выбранном руководстве предупреждение появляется, когда запуск планирует больше агентов, чем указано в руководстве ([Стоимость](https://code.claude.com/docs/en/workflows#cost)).

Один из способов достичь этого: напишите первую версию с запросом «use a workflow» для одной папки и сохраните её, как в шаге 6. Затем запустите `/workflow-authoring`, который загружает справочник, используемый Claude при написании скриптов, и попросите Claude изменить сохранённый скрипт так, чтобы он брал папку из `args` ([Редактирование сохранённого скрипта](https://code.claude.com/docs/en/workflows#edit-a-saved-script)). Выполните `/reload-skills`, затем попросите `Run /<name> on <folder>`.

Когда скрипт будет соответствовать остальным критериям, закоммитьте его. Затем запустите его по имени на двух разных папках, не редактируя между запусками. После каждого запуска попросите Claude сохранить отчёт:

```text
Save that report to .practice/a-3-run1.md: the folder you ran it on as the first line, then one line per item that still applies, starting with its path:line, and nothing else.
```

Для второй папки используйте `.practice/a-3-run2.md`.

## Проверка

Вы закончили, когда все следующие условия истинны:

- [ ] Закоммиченный скрипт в `.claude/workflows/` имеет литерал `export const meta` с `name` и `description` в качестве первого оператора и читает входные данные из `args`: `git ls-tree -r --name-only HEAD .claude/workflows` выводит его.
- [ ] `.practice/a-3-run1.md` и `.practice/a-3-run2.md` называют две разные папки в первых строках, и каждый содержит хотя бы один `path:line` внутри своей папки.
- [ ] Каждый указанный `path:line` существует и содержит `TODO` или `FIXME`.
- [ ] Самопроверка (не тестируется): вы запускали сохранённый рабочий процесс по имени для обоих отчётов, не редактируя его между запусками, и ни один запуск не показал предупреждение `Large workflow` на панели задач.

Выполните `npm run check -- a-3 --dir <your repo>` из вашей копии практики.

Если первый пункт не выполняется, проверьте, что скрипт закоммичен (`git check-ignore -v .claude/workflows/<file>.js` покажет правило игнорирования, если оно есть; добавьте его с помощью `git add -f` и закоммитьте) и что он читает `args`. Если отчёт содержит `path:line` вне своей папки или ни одного внутри неё, убедитесь, что скрипт читает папку из `args` и сообщает только о файлах внутри неё, запускайте `claude` из корня репозитория, чтобы пути начинались оттуда, и запустите его снова на папке, где `TODO` или `FIXME` всё ещё актуален. Если указанная строка не содержит `TODO` или `FIXME`, либо отчёт ссылается на другие строки в обоснованиях, либо файл изменился после запуска: попросите Claude ссылаться только на строки `TODO` и `FIXME` или запустите рабочий процесс снова и сохраните новый отчёт с помощью приведённого выше промпта.

## Будьте внимательны

- В автоматическом режиме Claude Code спрашивает только перед первым запуском рабочего процесса: любой ответ **Yes** записывает согласие в ваши пользовательские настройки, и последующие запуски начинаются без вопросов. Агенты рабочего процесса используют ваши правила разрешений, и когда ваша сессия находится в режиме accept-edits, auto или bypass, они работают в том же режиме ([Одобрение плана перед запуском](https://code.claude.com/docs/en/workflows#approve-the-plan-before-it-runs), [Режимы разрешений](https://code.claude.com/docs/en/sub-agents#permission-modes)). Читайте каждый скрипт перед одобрением и оставайтесь в ручном режиме для рабочего процесса, который вы ещё не читали.
- Запуск может использовать значительно больше токенов, чем та же задача в разговоре, и это учитывается в лимитах использования и скорости вашего тарифа. Сначала попробуйте рабочий процесс на одной небольшой папке и попросите Claude использовать более слабую модель для этапов, которым не нужна самая сильная. `/workflows` показывает использование токенов каждым агентом по мере выполнения, а `x` на выбранном запуске останавливает его. Когда запуск становится необычно большим, в строке прогресса появляется предупреждение `Large workflow`. После выбора руководства по размеру количество агентов заменяет встроенный порог предупреждения, но большой прогнозируемый объём токенов всё равно может его вызвать. Предупреждение не приостанавливает и не ограничивает запуск ([Стоимость](https://code.claude.com/docs/en/workflows#cost)).
- `p` приостанавливает и возобновляет запуск, но остановленный запуск не возобновляется с помощью `p`: попросите Claude перезапустить его с тем же скриптом в той же сессии или в сессии, которую вы откроете заново с помощью `claude --resume`. Агенты, которые ещё работали при остановке, начинают заново ([Возобновление после паузы](https://code.claude.com/docs/en/workflows#resume-after-a-pause)). Агент, чей вывод останавливается слишком надолго, также перезапускается самостоятельно, и `/workflows` добавляет `(retry 1)` к его имени ([Когда агент зависает и перезапускается](https://code.claude.com/docs/en/workflows#when-an-agent-stalls-and-restarts)). В версии v2.1.285 агент также перезапускается с начала своего промпта, если его соединение зависает на несколько минут в середине ответа (исправлено в v2.1.286) или ваш Mac выходит из сна (исправлено в v2.1.290) ([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)), поэтому не давайте машине засыпать во время работы.
