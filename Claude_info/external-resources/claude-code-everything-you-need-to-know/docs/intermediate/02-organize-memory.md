# Организуйте память проекта и смотрите, что загрузилось

<sub>**Intermediate** · Урок 2 из 8 · около 20 минут · Требуется: [Превратите повторяющийся рабочий процесс в skill](01-first-skill.md) · Проверено с Claude Code v2.1.292 (stable) 2026-10-15</sub>

## Цель

К концу этого урока вы сможете разделить инструкции проекта на импорты и правила с ограниченной областью действия, а также выяснить, какие файлы инструкций загрузились, когда Claude не следует одному из них.

## Вам понадобится

- Один из ваших собственных репозиториев с закоммиченным `CLAUDE.md`, как оставлено в [уроке 5 для начинающих](../beginner/05-project-memory.md), и ваша копия шаблона для практики с Node.js LTS: проверка выполняется из копии. Чтобы практиковаться вместо этого в копии шаблона, используйте её для обоих. Настройте папку `.practice/` репозитория, как описано в [уроке 1 для начинающих](../beginner/01-install-and-look-around.md#you-need), если ещё не сделали.
- `jq` для журнала загрузки в рабочем примере.
- Использование: лёгкое.

## Идея

Длинный `CLAUDE.md` трудно поддерживать, и каждая его строка загружается в каждую сессию. Два инструмента разделяют его ([Как Claude помнит ваш проект](https://code.claude.com/docs/en/memory)):

- **Импорт** — строка вида `@docs/conventions.md` в `CLAUDE.md`, загружает другой файл вместе с ним. Это организует файл, но не экономит контекст.
- **Правило** — это Markdown-файл в `.claude/rules/`. С frontmatter `paths:` оно загружается только тогда, когда Claude работает с соответствующим файлом.

| Файл инструкций | Загружается |
|---|---|
| `CLAUDE.md` в корне проекта и правило без `paths:` | При запуске сессии |
| Файл, указанный в импорте `@path` | Вместе с файлом, который его импортирует |
| Правило с `paths:` | Когда Claude читает, записывает или редактирует соответствующий файл с помощью своих инструментов Read, Write или Edit |
| Автопамять — заметки, которые Claude хранит для себя | При запуске сессии: первые 200 строк или 25 КБ его индекса `MEMORY.md` |

Когда Claude игнорирует инструкцию, сначала выясните, загрузился ли её файл. Если да, вероятная проблема — формулировка: сделайте её конкретной и удалите любую инструкцию, которая ей противоречит ([Отладка вашей конфигурации](https://code.claude.com/docs/en/debug-your-config#see-what-loaded-into-context)).

## Рабочий пример

1. В вашем репозитории добавьте импорт в `CLAUDE.md`. В шаблоне для практики импортируйте `package.json`; в вашем собственном репозитории — документ, который ведёт ваша команда, например `@docs/architecture.md`:

   ```markdown
   - npm scripts: @package.json
   ```

   Путь импорта продолжается до первого пробела, поэтому не ставьте точку сразу после него.
2. Сохраните правило для ваших тестовых файлов как `.claude/rules/testing.md`. Измените шаблон, чтобы он соответствовал месту, где находятся ваши тесты:

   ```markdown
   ---
   paths:
     - "test/**/*.js"
   ---

   # Тестирование

   - Используйте `node:test` и `node:assert/strict`; никаких других библиотек для тестирования.
   ```

3. Сохраните этот журнал загрузки в `.practice/i-2-hook.json`. Это хук [`InstructionsLoaded`](https://code.claude.com/docs/en/hooks#instructionsloaded): каждый раз, когда загружается `CLAUDE.md`, правило или импортированный файл, он добавляет причину и путь файла в `.practice/i-2-loaded.txt`. Он не записывает ничего другого и работает только в сессиях, которые вы запускаете с ним:

   ```json
   {
     "hooks": {
       "InstructionsLoaded": [
         { "hooks": [ { "type": "command", "command": "jq -r '[.load_reason, .file_path] | @tsv' >> \"$CLAUDE_PROJECT_DIR/.practice/i-2-loaded.txt\"" } ] }
       ]
     }
   }
   ```

4. Запустите сессию с журналом, `claude --settings .practice/i-2-hook.json` ([Справочник по CLI](https://code.claude.com/docs/en/cli-reference#cli-flags)), и выполните `/context all`: обычный `/context` может свернуть свой список, а `all` разворачивает его ([Команды](https://code.claude.com/docs/en/commands)). В разделе **Memory files** перечислены файлы инструкций, загруженные при запуске, например `CLAUDE.md` ([Настройка проекта CLAUDE.md](https://code.claude.com/docs/en/memory#set-up-a-project-claude-md)). Правила с ограниченной областью среди них нет: ещё ничто не читало тестовый файл.
5. Попросите Claude прочитать тестовый файл с помощью его инструмента Read. Назовите инструмент: Claude иногда читает файл через команду оболочки, что не загружает правила с ограниченной областью.

   ```text
   Используйте ваш инструмент Read, чтобы прочитать test/config.test.js, затем скажите мне в одном предложении, что он проверяет.
   ```

   Во втором терминале `cat .practice/i-2-loaded.txt` показывает каждую загрузку с её причиной: `session_start` для `CLAUDE.md`, `include` для `package.json`, и теперь `path_glob_match` для правила.

## Ваша очередь

Правило товарища по команде никогда не срабатывает. Выясните почему и исправьте.

1. Сохраните это правило как `.claude/rules/cli.md`. В вашем собственном репозитории напишите правило для одной из ваших папок с исходным кодом и намеренно допустите опечатку в имени папки в его шаблоне:

   ```markdown
   ---
   paths:
     - "source/**/*.js"
   ---

   # Вывод CLI

   - Выводите ошибки в stderr, начиная с `linkcheck:`.
   ```

2. Запустите сессию с журналом, `claude --settings .practice/i-2-hook.json`, и попросите Claude использовать его инструмент Read для `src/cli.js` или для файла в вашей папке.
3. Прочитайте журнал: правило никогда не загружалось. Сравните его шаблон с существующими файлами, `git ls-files src`.
4. Исправьте шаблон, запустите новую сессию с журналом и повторите шаг 2. Теперь в журнале есть строка `path_glob_match` для `cli.md`.
5. Закоммитьте `CLAUDE.md` и `.claude/rules/`. Удалите `.practice/i-2-hook.json`, когда журнал больше не нужен.

## Проверка

Вы закончили, когда всё следующее верно:

- [ ] Закоммиченный `CLAUDE.md` импортирует существующий файл: `git show HEAD:CLAUDE.md | grep '@'` показывает импорт.
- [ ] Каждое закоммиченное правило с `paths:` соответствует файлу: для каждого шаблона `git ls-files ':(glob)<pattern>'` выводит хотя бы один файл. С префиксом `:(glob)` `*` в git остаётся внутри одной папки, а `**/` соответствует любому количеству папок, как в правилах ([gitglossary: pathspec](https://git-scm.com/docs/gitglossary#Documentation/gitglossary.txt-aiddefpathspecapathspec)). Git не раскрывает фигурные скобки, а правила раскрывают ([Правила для конкретных путей](https://code.claude.com/docs/en/memory#path-specific-rules)), поэтому проверяйте шаблон вида `src/**/*.{ts,tsx}` по одному расширению за раз.
- [ ] Журнал показывает загрузку импорта и правила с ограниченной областью: `grep -E '^(include|path_glob_match)' .practice/i-2-loaded.txt` выводит хотя бы по одной строке каждого вида.
- [ ] Самопроверка (не тестируется): вы можете сказать, какие из ваших файлов инструкций загружаются при запуске, а какие позже, и как вы увидели загрузку каждого.

Запустите `npm run check -- i-2 --dir <your repo>` из вашей копии для практики или `npm run check -- i-2` в самой копии.

Если проверка импорта не проходит, ищите знак препинания сразу после пути или путь, записанный относительно неправильной папки: импорт разрешается от файла, который его содержит. Если правило не соответствует ни одному файлу, его шаблон относителен к корню проекта, поэтому `source/**` не соответствует ничему в проекте, код которого находится в `src/`. Если в журнале нет строки `path_glob_match`, запустите сессию с `--settings .practice/i-2-hook.json` и попросите инструмент Read по имени.

## Осторожно

- Импорт, указывающий за пределы вашего рабочего каталога, например `@~/notes.md`, запрашивает ваше одобрение при первом использовании в проекте; если вы отклоните, он останется выключенным ([Импорт дополнительных файлов](https://code.claude.com/docs/en/memory#import-additional-files)).
- Claude Code читает `CLAUDE.md` проекта один раз, при запуске. Изменение в нём достигает сессии после `/clear`, `/compact` или перезапуска ([Редактирование CLAUDE.md в середине сессии](https://code.claude.com/docs/en/prompt-caching#editing-claude-md-mid-session)).
- Чтобы найти инструкции, которые противоречат друг другу или называют несуществующие файлы, запустите `/doctor prompt-audit` ([Аудит ваших файлов инструкций](https://code.claude.com/docs/en/memory#audit-your-instruction-files)). Он предлагает правки и ничего не меняет, пока вы не попросите.
