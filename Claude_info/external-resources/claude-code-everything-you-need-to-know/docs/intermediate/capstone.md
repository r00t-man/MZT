# Промежуточный капстоун: подготовьте репозиторий для нового коллеги

<sub>**Промежуточный** · Капстоун · 30–60 минут · Требуется: восемь [промежуточных уроков](README.md) или их навыки · Проверено на Claude Code v2.1.292 (stable) 2026-10-15</sub>

Это задание объединяет весь промежуточный уровень. Готового примера нет: в брифе сказано, что нужно команде, а как это построить — решаете вы. [Промежуточный выход](README.md#by-the-end-of-this-level-you-can) — список того, что вы умеете к концу уровня. Проверка читает то, что вы закоммитили, а остальное из выхода вы отмечаете сами в разделе [Что проверка не видит](#what-the-check-cant-see).

## Вам понадобится

- Ваша копия шаблона для практики без незакоммиченных изменений и Node.js LTS. Капстоун выполняется только в копии шаблона. Если `git status --porcelain` показывает файлы, закоммитьте их или временно уберите с помощью `git stash push --include-untracked`.
- `jq` и `python3` для скриптов-хуков, а также Chrome для MCP-сервера.
- macOS, Linux или WSL 2: песочнице нужна одна из этих систем ([Настройка на Windows](https://code.claude.com/docs/en/setup#set-up-on-windows)), а скрипты-хуки в уроках написаны на bash.
- Использование: умеренное.

## Задание

В понедельник к команде присоединяется новый коллега. Бриф находится в `capstone/intermediate-brief.md` в вашей копии для практики: настройте репозиторий так, чтобы сессии Claude Code у него работали так же, как у команды, и закоммитьте всё, потому что он получит только то, что есть в git.

Соберите каждую часть так, как учили в соответствующем уроке:

1. **Навык**, который запускает проверку ссылок в папке и объясняет каждую битую ссылку. Он запускается по имени и загружается сам, когда кто-то просит проверить ссылки ([урок 1](01-first-skill.md)).
2. **Память проекта:** `CLAUDE.md` импортирует `package.json`, а соглашения по тестированию находятся в правиле в `.claude/rules/`, ограниченном файлами в `test/` ([урок 2](02-organize-memory.md)).
3. **Командные настройки** в закоммиченном `.claude/settings.json`: запретить чтение файлов `.env` и `.env.*`, разрешить `npm test` и включить песочницу ([урок 4](04-permissions-and-sandbox.md)). `/sandbox` сохраняет в ваш локальный файл, которого нет у коллег, поэтому добавьте `"sandbox": {"enabled": true}` в общий файл.
4. **Хук**, который блокирует инструменты Edit и Write Claude внутри `samples/` и только там: тесты зависят от точного содержимого этих файлов ([урок 5](05-hooks.md)).
5. **Суб-агент-ревьюер** с инструментами только для чтения ([урок 6](06-subagents.md)).
6. **Chrome DevTools MCP** на уровне проекта, закреплённый, с отключёнными статистикой использования, запросами CrUX и проверками обновлений ([урок 7](07-mcp.md)).
7. **Плагин `claude-code-setup`**, включённый для всех на уровне проекта и установленный ([урок 8](08-plugins.md)).

Затем в сессии попробуйте каждую часть: запустите навык по имени, попросите Claude отредактировать файл в `samples/` с помощью инструмента Edit, делегируйте ревью, одобрите MCP-сервер и используйте один из его инструментов. Выбирайте модель и уровень усилий для каждой задачи, как показано в [уроке 3](03-model-and-effort.md). Закоммитьте всё и убедитесь, что `npm test` по-прежнему проходит.

## Проверка

Вы закончили, когда все следующие пункты истинны:

- [ ] Закоммиченный навык проекта запускает проверку ссылок по имени и может загружаться сам.
- [ ] Закоммиченный исполняемый хук `PreToolUse` для Edit и Write блокирует `samples/` и ничего больше.
- [ ] Закоммиченный суб-агент-ревьюер имеет только инструменты для чтения.
- [ ] Закоммиченный `.mcp.json` запускает chrome-devtools-mcp точной версии с отключёнными статистикой использования, запросами CrUX и проверками обновлений.
- [ ] Закоммиченный `.claude/settings.json` включает плагин из одного из маркетплейсов Anthropic.
- [ ] Закоммиченный `.claude/settings.json` запрещает чтение файлов `.env` и разрешает узкую тестовую команду.
- [ ] Закоммиченный `.claude/settings.json` включает песочницу, а `.claude/settings.local.json` не попадает в git.
- [ ] Закоммиченный `CLAUDE.md` импортирует файл с помощью `@path`, и файл существует.
- [ ] Закоммиченное правило в `.claude/rules/` ограничено с помощью `paths:`, и каждое ограниченное правило соответствует файлу в репозитории.
- [ ] `npm test` проходит, и `git status --porcelain` ничего не выводит.

Запустите `npm run check -- i-capstone` в вашей копии для практики. Для каждого непройденного пункта будет выведено, что исправить.

## Что проверка не видит

Проверка не смотрит на эти части промежуточного выхода. Отметьте их сами, честно:

- [ ] Я запустил свой навык по имени, и Claude загрузил его сам, когда я попросил проверить ссылки.
- [ ] Я видел, как мой хук заблокировал Edit в `samples/` во время сессии.
- [ ] Я делегировал ревью своему суб-агенту, и вернулось только его резюме.
- [ ] Я одобрил MCP-сервер в сессии и использовал один из его инструментов.
- [ ] Я установил плагин командой `claude plugin install claude-code-setup@claude-plugins-official --scope project`, как это сделает коллега после получения настроек.
- [ ] Я могу выбрать модель и уровень усилий для задачи и объяснить почему.
- [ ] Когда Claude не выполнил инструкцию, я могу выяснить, загрузился ли его файл.

Когда все чекбоксы на этой странице отмечены, вы готовы к [продвинутому уровню](../advanced/README.md). Его список «готов, если» — это промежуточный выход.

Если этот уровень помог, поставьте звезду — это поможет другим разработчикам найти руководство.
