### Время ответа

На issue об устаревшем контенте первый ответ даётся в течение 7 дней: исправление или источник уровня Tier 1, который решает вопрос. На issue с отзывом об уроке первый ответ также даётся в течение 7 дней.

## Источники и цитирование

### Какой источник считается

Для каждого вида утверждений есть один источник **Tier 1**. Это авторитетный источник для такого рода утверждений.

| Утверждение | Источник Tier 1 |
|---|---|
| Поведение Claude Code: команды, флаги, настройки, события hook, метки стабильности | [code.claude.com/docs](https://code.claude.com/docs) |
| Когда что-то вышло, версии, каналы выпуска | [CHANGELOG anthropics/claude-code](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md); npm-теги `latest` и `stable` пакета `@anthropic-ai/claude-code` |
| Модели, идентификаторы моделей, лимиты API | [документация platform.claude.com](https://platform.claude.com/docs) |
| Цены и возможности тарифных планов | [claude.com/pricing](https://claude.com/pricing) и статьи поддержки по планам на [support.claude.com](https://support.claude.com) |
| Цены API | [цены platform.claude.com](https://platform.claude.com/docs/en/about-claude/pricing) |
| Протокол MCP | [modelcontextprotocol.io](https://modelcontextprotocol.io) |
| Поведение GitHub | [docs.github.com](https://docs.github.com) |
| Установка и использование стороннего инструмента | Собственный репозиторий или документация этого инструмента |

- **Tier 2** — любой другой первоисточник: support.claude.com, новости и инженерные посты anthropic.com, claude.com/blog, [Claude Academy](https://academy.claude.com), README первоисточников и официальный плагин [`marketplace.json`](https://github.com/anthropics/claude-plugins-official/blob/main/.claude-plugin/marketplace.json).
- **Tier 3** — всё остальное. Указывайте источник в предложении и никогда не используйте его как единственный источник сведений о поведении Claude Code.

### Когда источники расходятся

1. Побеждает источник Tier 1 для данного вида утверждений.
2. Внутри одного уровня более конкретная страница имеет приоритет над общей, затем более новая или привязанная к версии страница — над более старой.
3. Документация выигрывает в вопросах текущего поведения; CHANGELOG — в вопросах, когда что-то изменилось.
4. Если это не решает вопрос, укажите только то, что поддерживают оба источника, или исключите утверждение. Никогда не выбирайте сторону молча: зафиксируйте конфликт в описании PR.

Два открытых конфликта, зафиксированных 2026-10-05:

- На [странице настройки](https://code.claude.com/docs/en/setup) сказано, что npm-пакет требует «Node.js 22 или новее»; в статье поддержки [Ваш первый день в Claude Code](https://support.claude.com/en/articles/14552382-your-first-day-in-claude-code) сказано «npm (Node 18+)». Побеждает страница настройки: это Tier 1, статья — Tier 2.
- В [документации по стилям вывода](https://code.claude.com/docs/en/output-styles) Learning указан как встроенный стиль; в официальном `marketplace.json` он назван «невыпущенным стилем вывода Learning». Документация выигрывает по той же причине.

### Что требует цитирования

**Изменчивое утверждение** — это утверждение, которое может устареть. Каждое изменчивое утверждение нуждается в источнике:

- версия или дата
- цена, доступность плана, лимит использования или скорости
- название модели, идентификатор модели или значение по умолчанию
- название или поведение команды, флага, настройки, переменной окружения, события hook, инструмента или поля frontmatter
- метка стабильности (preview, beta, research preview, deprecated), скопированная дословно из источника Tier 1
- любое количество или статистика
- факт о статусе третьей стороны: владелец, лицензия, архивирован

Ментальные модели, аналогии, собственные советы руководства и шаги инструкций, команды которых уже процитированы на той же странице, не требуют цитирования.

### Как цитировать

- Ставьте ссылку на страницу Tier 1 в тексте при первом упоминании каждого изменчивого утверждения на странице, а не при каждом повторе.
- Каждая страница со [штампом](#the-stamp), а также этот файл, имеет однострочный нижний колонтитул `Sources:` после своего содержимого. За ним следует только строка навигации: на уроке — та, что описана в [Уроках](#lessons); на других страницах — ссылка `Up:`. В нижнем колонтитуле перечислены все страницы, на которые опираются утверждения страницы: каждая страница, указанная как источник факта, который она утверждает.
  - Ссылки, не подтверждающие никаких утверждений, можно не перечислять: дополнительная литература (Go further, Official companions, Related pages), страницы загрузки и установки, формы issue этого репозитория и шаблон практики, а также указатели, говорящие, где искать, например сайты в таблице Tier 1.
  - Страница, состоящая из ссылок на свои источники, может назвать их в сводке, как это делают Further learning («страницы, указанные выше») и Feature map («связанная страница каждой функции»). Страница, не опирающаяся на внешние страницы, не нуждается в нижнем колонтитуле.
  - README, другие файлы сообщества и заглушки не нуждаются в нижнем колонтитуле.
- Привязывайте утверждения, чувствительные к дате, к версии (`v2.1.x`) или полной дате.
- Не добавляйте даты обращения в текст.

```markdown
Set `disable-model-invocation: true` to stop Claude from loading a skill on its own ([Skills](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill)).

Sources: [Skills](https://code.claude.com/docs/en/skills), [Permissions](https://code.claude.com/docs/en/permissions)
```

### Чего нет в руководстве

- Никаких цен, промоакций, лимитов планов, дат вывода из эксплуатации, таблиц спецификаций моделей или текста «по состоянию на». Штамп страницы несёт дату для всего на ней. Любая другая цифра, действительно необходимая уроку, пишется с полной датой в предложении (`on <полная дата>, ...`) плюс ссылка.
- Метки стабильности цитируются дословно в предупреждении `> [!NOTE]` под заголовком, никогда в тексте заголовка.
- Будущая дата встречается редко. Она получает полную дату, ссылку Tier 1 и маркер истечения после предложения: `<!-- expires: YYYY-MM-DD -->`. Проверки pull request предупреждают, но не блокируют, когда маркер должен истечь в течение 30 дней.

### Штамп

Уроки, элективы, капстоуны, индексы уровней, индексы тем и справочные страницы, не являющиеся заглушками, несут штамп как последнее поле строки заголовка под своим H1:

```text
Verified against Claude Code vX.Y.Z (stable) on YYYY-MM-DD
```

Он удостоверяет, что на эту дату каждое изменчивое утверждение на странице было проверено по его источнику Tier 1 на этой `stable` версии, и что упражнение и проверка страницы, если таковые имеются, были прогонены там. Он не удостоверяет сторонние элементы за пределами [панели списков](#the-listing-bar) или поведение на других каналах выпуска и поверхностях. README, файлы сообщества и заглушки не несут штампа.

Правило `stamps` в [проверках](#checks) не проходит на странице со штампом, если штамп отсутствует или имеет неверный формат. Как только README получает полосу доверия, оно также не проходит, если версия полосы отличается от последней записи издания в [CHANGELOG.md](CHANGELOG.md).

### Издания и исправления

У каждого выпуска есть запись в [CHANGELOG.md](CHANGELOG.md), новые сверху:

- издание: `## vYYYY.MM - YYYY-MM-DD`, со строкой `Verified against Claude Code vX.Y.Z (stable).` под ним;
- исправление: `## vYYYY.MM.N - YYYY-MM-DD`.

Отправка тега `v*` запускает проверку издания. На теге издания штамп каждой страницы со штампом должен называть версию издания. На теге исправления каждая страница со штампом, изменённая с предыдущего тега, должна нести штамп с датой после записи этого тега.

### Числа, бенчмарки и оценки

| Вид | Правило |
|---|---|
| Любое число | Никаких чисел без датированного, связанного источника. Вырезайте числа без источника или переформулируйте предложение без них. Собственные метаданные руководства, такие как оценка времени урока, не нуждаются в источнике. |
| Количество принятия третьими сторонами (звёзды, загрузки, установки) | Не включайте их в текст руководства; им место в issue с предложением ресурса, где элемент был рассмотрен. Исключение: цифра экосистемы, необходимая уроку, пишется с полной датой в предложении (`on <полная дата>, ...`) плюс ссылка, никогда не `as of`. Собственный значок звёзд README допустим. |
| Бенчмарки вендоров | Всегда указывайте их в предложении («Anthropic сообщает ...») и давайте ссылку. |
| Оценки лимитов планов третьими сторонами | Вырезайте их и вместо этого давайте ссылки на официальные страницы планов: [What is the Pro plan?](https://support.claude.com/en/articles/8325606-what-is-the-pro-plan), [What is the Max plan?](https://support.claude.com/en/articles/11049741-what-is-the-max-plan), [Use Claude Code with your Pro or Max plan](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan). |
| Эвристики автора | Переформулируйте их как совет без выдуманной точности: «обычно исправление находится выше по течению», а не «~80% случаев». |

### Недокументированное поведение

Руководство не учит поведению, которое не задокументировано ни одним источником Tier 1 или Tier 2. Если урок не может работать без него, поднимите вопрос с мейнтейнером; оно включается только с одобрения мейнтейнера.

## Политика списков

Листинг — это внешний элемент, на который руководство указывает как на что-то для использования или чтения: инструмент, MCP-сервер, skill, плагин, курс или статья.

### Где появляются листинги

- Сторонний элемент появляется только там, где урок его использует. Элементы от Anthropic или проекта MCP могут также появляться на справочной странице, которая их использует.
- Никаких каталогов. Каждая тема заканчивается одним указателем «Найти больше»: маркетплейсы плагинов Anthropic и [MCP Registry](https://registry.modelcontextprotocol.io) (помеченный «preview», [его собственная формулировка](https://modelcontextprotocol.io/registry/about)), плюс не более двух курируемых списков, прошедших планку листинга.
- Списки без ссылок, только с именами, вырезаются.

### Метки

Каждый листинг несёт одну метку:

| Метка | Значение |
|---|---|
| **Anthropic** | Сделано Anthropic |
| **Vendor** | Собственный инструмент производителя для его продукта, например MCP-сервер Playwright от Microsoft или эталонные серверы проекта MCP |
| **Community** | Любой другой сторонний элемент |

Каждый раздел с листингами несёт одну строку: `Listings checked against the listing bar on <полная дата>.` Строки не содержат дат.

### Планка листинга

Чтобы добавить любой другой элемент Vendor или Community, должны выполняться все правила добавления. При каждой проверке элемент удаляется, если выполняется любое правило удаления. Tier 1 означает авторитетный источник для такого рода утверждений, например [code.claude.com/docs](https://code.claude.com/docs) для поведения Claude Code.

| Проверка | Правило добавления (все должны выполняться) | Правило удаления (любое удаляет элемент) |
|---|---|---|
| Урок | Именованный урок нуждается в нём | Нет правила |
| Лицензия | Публичный репозиторий с [лицензией, одобренной OSI](https://opensource.org/licenses) (CC BY, CC BY-SA или CC0 для ресурсов только с документацией) | Нет правила |
| Активность | Коммит в ветку по умолчанию за последние 90 дней | Нет коммитов в ветку по умолчанию за 12 месяцев |
| Принятие | Не менее 1000 звёзд на GitHub, или не менее 1000 еженедельных загрузок npm или PyPI, или не менее 10000 установок из маркетплейса, измеренных на указанную дату | Менее 100 звёзд и менее 1000 еженедельных загрузок, без листинга в маркетплейсе Anthropic |
| Точность | Ничто из того, что он говорит о Claude Code, не противоречит Tier 1 | Противоречит Tier 1 |
| Хостируемый сервис | Его основная функция не зависит от проприетарного хостируемого сервиса, если только это не собственный инструмент производителя для его продукта, помеченный `needs a <vendor> account` | Нет правила |
| Статус | Нет правила | Заархивирован или устарел в апстриме, или его канонический URL или репозиторий возвращает 404 |

**Элементы Anthropic и проекта MCP** нуждаются только в уроке или справочной странице, которые их используют, живом URL и отсутствии дисклеймера «не поддерживается» или «не официально». Это включает эталонные серверы проекта MCP, которые несут метку Vendor, потому что метка называет производителя.

### Предостережение о безопасности

Каждый раздел, который перечисляет элемент, запускающий код или получающий доступ к инструментам (MCP-серверы, хуки, плагины, навыки со скриптами), несёт эту строку один раз:

> Сторонний элемент: он может запускать код на вашей машине или давать Claude новые инструменты. Проверьте его перед установкой; это руководство не проводит его аудит.

Руководство не проводит аудит безопасности листингов.

### Предложение ресурса

- Листинги добавляются при проверке контента, а не через pull request участников. Листинг, добавленный при проверке, ссылается на pull request этой проверки. Чтобы предложить ресурс, используйте [форму Suggest a resource](https://github.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know/issues/new?template=suggest-resource.yml); её обязательные поля запрашивают доказательства, необходимые планке.
- Незапрошенный pull request, добавляющий листинг, закрывается с ответом, указывающим на форму.
- Предложения, прошедшие планку, ждут следующей проверки контента. Ничто не сливается ad hoc.
- Предлагать собственный проект разрешено. Раскройте свою аффилиацию; применяется та же планка.

## Вклад с помощью ИИ

Вклад с помощью ИИ разрешён, и раскрывать его не нужно. Вы владеете каждым утверждением, которое отправляете, применяются те же правила цитирования, и pull request с утверждениями, которые невозможно проверить, закрываются, кто бы или что бы их ни написал.

## Pull request

Каждый pull request несёт одно изменение. Заполните каждый раздел [шаблона pull request](https://github.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know/blob/main/.github/PULL_REQUEST_TEMPLATE.md), который применим.

- **Базовый уровень.** Изменения проверяются на одной `stable` версии Claude Code, названной в записи Unreleased файла [CHANGELOG.md](CHANGELOG.md) и замороженной во время сборки издания. Более поздний `stable` релиз подтягивается рано только тогда, когда он удаляет, переименовывает или меняет значение по умолчанию чего-то, чему учит урок, отдельным pull request. Перед выпуском издания финальный проход проверяет каждую отштампованную страницу на текущем `stable` и перештамповывает её.
- **Таблица утверждений.** Каждое изменчивое утверждение, добавленное или изменённое, ссылается на свой источник Tier 1. Описание содержит таблицу утверждений (утверждение, источник, результат), заполненную вторым, независимым проходом, который пытался опровергнуть каждое утверждение по Tier 1: отдельный агент для pull request, сделанных агентом, ревьюер для человеческих.
- **Поле Tested.** Pull request, затрагивающий `examples/` или `.claude/`, указывает `Tested in Claude Code vX.Y.Z on <OS>` или «smoke test only», если изменение не запускалось в сессии.
- **Dry-run.** Pull request уроков и pull request примеров, чей пример используется основным уроком или capstone, записывают dry-run каждого упражнения и проверку на базовом уровне, в чистой конфигурации:
  1. Установите базовую версию с помощью `curl -fsSL https://claude.ai/install.sh | bash -s <version>` ([Advanced setup](https://code.claude.com/docs/en/setup)).
  2. После установки экспортируйте `DISABLE_UPDATES=1` в оболочке dry-run. Нативная установка продолжает обновляться в фоновом режиме ([Advanced setup](https://code.claude.com/docs/en/setup#auto-updates)), и эта переменная блокирует все пути обновления ([Environment variables](https://code.claude.com/docs/en/env-vars)).
  3. Укажите `CLAUDE_CONFIG_DIR` на свежую папку, единственный файл в которой — `settings.json`, содержащий `{"syncClaudeAiSkills": false, "syncClaudeAiPlugins": false, "disableClaudeAiConnectors": true}`, или используйте выделенный тестовый аккаунт с теми же настройками ([Settings](https://code.claude.com/docs/en/settings)). Пустая папка конфигурации сама по себе всё равно загружает синхронизированные навыки, плагины и коннекторы аккаунта claude.ai, под которым вы вошли.
  4. Запишите `claude --version` в начале и в конце (прогон, у которого две версии различаются, не засчитывается), вывод `/skills` и `/mcp`, ОС, выполненные шаги и вывод проверки в разделе dry-run шаблона.
- **Изображения.** Гигиена захвата и контраст ([Diagrams and images](#diagrams-and-images)) являются пунктами проверки в шаблоне, потому что CI не может их оценить.
- **Ревью.** Мейнтейнер ревьюит и сливает каждый pull request ([CODEOWNERS](https://github.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know/blob/main/.github/CODEOWNERS)).

### Проверки

Перед открытием pull request запустите проверки руководства на вашем рабочем дереве, из корня репозитория:

```bash
node .github/scripts/check.mjs
```

Требуется Node.js LTS, git, Ruby (для YAML), jq (для smoke-тестов примеров), [shellcheck](https://github.com/koalaman/shellcheck) и [lychee](https://github.com/lycheeverse/lychee) 0.24 в вашем `PATH`; установите `LYCHEE` или `SHELLCHECK`, чтобы указать на бинарник в другом месте. Каждое правило печатает `PASS`, `FAIL`, `WARN` или `SKIP` со своим именем, и команда завершается с ненулевым кодом, если какое-либо правило не прошло. CI pull request запускает ту же команду с `--base`, установленным на целевую ветку; правила с ограничением по diff сравнивают с `origin/main` локально.

| Правило | Не проходит, когда |
|---|---|
| `internal-links` | Ссылка или фрагмент внутри репозитория не разрешается |
| `anchor-diff` | Якорь в `anchors.txt` или на базовой ветке исчез |
| `stub-paths` | Путь страницы в `paths.txt` исчез |
| `stamps` | Штамп отштампованной страницы отсутствует или имеет неверный формат, или полоса доверия не согласуется с CHANGELOG |
| `edition-gate` | Только на релизном теге: отштампованная страница не соответствует релизу |
| `expiry` | Никогда на pull request, где предупреждает о маркерах, срок которых истекает в течение 30 дней |
| `em-dash` | В добавленной строке есть длинное тире вне кода и двойных кавычек |
| `images` | У изображения нет alt-текста, у блока Mermaid нет строк доступности, или файл в `assets/` нарушает правила именования, ссылок или размера |
| `lesson-lint` | Урок или Elective нарушает [анатомию урока](#lessons) |
| `static-validation` | JSON, YAML, frontmatter навыка или агента, скрипт рабочего процесса или shell-скрипт не парсится или не линтуется |
| `inertness` | `examples/` содержит путь, который Claude Code может загрузить сам, или манифест маркетплейса не переименован в `dot-claude-plugin/`, или корень репозитория содержит папку `.claude-plugin/` |
| `smoke-tests` | `test.sh` примера не проходит (только когда изменение затрагивает `examples/`) |
| `lesson-quotes` | С `LEARN_DIR`, установленным на папку `learn/lessons` чекаута практического шаблона, или в еженедельном прогоне: цитируемая строка, блок кода, заголовок, штамп или количество шагов в файле урока обучающего приложения шаблона больше не соответствует его уроку (цитаты и блоки кода разминки, более ранний урок или индекс уровня, названный в его строке `from`), или у блока кода нет закрывающей ограды. Страница индекса уровня (`docs/<level>/README.md`) может цитироваться с любого уровня: `learn.txt` перечисляет её как `<level>-index`, и при любом прогоне, включая pull request, проверка не проходит, когда этот id называет другую страницу; только разминка называет её, как `from: <level>-index`. Блок кода должен быть равен ограждённому блоку урока строка в строку, включая пустые строки, за вычетом отступа ограды урока, который должен быть не более трёх пробелов и вне цитаты или предупреждения. На pull request, который меняет урок или индекс уровня, перечисленный в `learn.txt`, только предупреждает |

У каждого правила есть заведомо плохие фикстуры в `.github/scripts/fixtures/`, по одной папке на случай: `fixture.json` называет правило, ожидаемый результат и, опционально, шаблоны `output`, которым должен соответствовать вывод проверки, `tree/` содержит файлы, `base/` — состояние до изменения, а `generate.mjs` записывает всё, что было бы живой конфигурацией Claude Code при коммите. Если вы меняете правило, запустите также самотест:

```bash
node --test '.github/scripts/test/**/*.test.mjs'
```

## Рутина мейнтейнера

Запланированные проверки следят за состоянием между изданиями. Каждая открывает или обновляет один отслеживающий issue и никогда не открывает pull request:

| Рабочий процесс | Запускается | Issue |
|---|---|---|
| Еженедельные внешние ссылки | По понедельникам | Сломанные внешние ссылки |
| Ежедневные маркеры истечения срока | Ежедневно | Устаревшие факты в руководстве |
| Еженедельный дрейф версий | По понедельникам | Новый стабильный релиз Claude Code |
| Еженедельные цитаты уроков | По понедельникам | Цитаты уроков разошлись с уроком |

Каждый месяц мейнтейнер:

1. Запускает аудит устаревших документов в сессии Claude Code в корне репозитория и заводит `issueBody`, который он возвращает, как один issue. Он сортирует изменчивые утверждения в README, страницах документации и README примеров как устаревшие, непроверяемые или нормальные и работает на Sonnet, если `model` не называет другую модель. Ежемесячный прогон проверяет только страницы, изменённые с последнего аудита, `/stale-docs-audit with args { "since": "<commit>" }`, используя коммит, названный в последнем issue аудита. Каждое издание начинается с полного прогона, `/stale-docs-audit`. Аудит работает на подписке Claude мейнтейнера, поэтому сначала снимите `ANTHROPIC_API_KEY`: когда он установлен, Claude Code использует ключ после вашего одобрения, а `claude -p` всегда использует его ([Authentication precedence](https://code.claude.com/docs/en/authentication#authentication-precedence)).
2. Запускает `gh workflow list --all` и снова включает любой отключённый запланированный рабочий процесс с помощью `gh workflow enable <workflow>`. В публичном репозитории GitHub отключает запланированные рабочие процессы после 60 дней без активности репозитория ([Disabling and enabling a workflow](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows)).

Каждые две недели мейнтейнер запускает `.github/scripts/traffic-snapshot.sh` и сохраняет его вывод. Он записывает, сколько посетителей переходит со страницы репозитория на каждый уровень, звёзды, добавленные за последние 30 дней, поисковые рефереры и issues с отзывами об уроках. Требуется собственный логин `gh` мейнтейнера, потому что API трафика требует доступ на запись, и он записывает уровень вне топ-10 путей GitHub как «below the 10th» ([Repository traffic](https://docs.github.com/en/rest/metrics/traffic)).

## Руководство по стилю документации

Руководство организовано как уроки трёх уровней: Начальный, Средний и Продвинутый. Новые и изменённые страницы следуют этим правилам.

### Уроки

Урок занимает от 10 до 20 минут и продвигает читателя на один шаг к одному can-do утверждению своего уровня. Каждый урок имеет следующую форму, в этом порядке:

1. H1 с названием урока, как первая строка.
2. Одна строка `<sub>` под ним: уровень жирным, позиция ("Урок N из M"), "около N минут", Необходимо (ссылки на предыдущие уроки), и [штамп](#the-stamp).
3. Шесть фиксированных слотов, с этими точными заголовками, чтобы каждый урок имел одинаковые якоря:
   - **Цель:** одно предложение, "К концу этого урока вы сможете ...".
   - **Вам нужно:** предыдущие уроки, окружение и где практиковаться. Вариантный callout (нативный Windows, разница в плане) идёт сюда, максимум один на вариант.
   - **Идея:** рабочая модель примерно в 150 словах максимум, плюс одна необязательная диаграмма урока.
   - **Рабочий пример:** нумерованные шаги по реалистичной задаче, с реальными командами и наблюдаемым состоянием после каждого шага.
   - **Ваш ход:** упражнение. Начальный повторяет пример с точными шагами; Средний завершает или исправляет частичный файл; Продвинутый получает краткое задание и критерии приёмки.
   - **Проверка:** список задач с наблюдаемыми критериями, с любым готовым тестом, который нужен; затем строка `npm run check -- <id>`, где проверка существует (основные уроки и capstones, не Элективы); затем максимум один диагноз "если нет" на каждый проверяемый пункт.
4. Необязательные слоты: **Осторожно** (максимум 3 пункта: безопасность, затем стоимость, затем подводные камни) и **Дальше** (максимум 3 ссылки).
5. Футер: строка `Источники:`; предыдущий, индекс уровня и следующий; одна ссылка `Тема:`; и "Застряли на этом уроке?".

Проверки тестируют состояние, которое может прочитать скрипт: состояние git, файлы, коды выхода и файлы настроек, никогда не формулировку ответа Claude. Представления только для сессии, такие как строка состояния или списки `/hooks` и `/context`, относятся к Рабочему примеру или к одному пункту самопроверки в Проверке, который помечен как не тестируемый. Состояние, которое существует только мгновение, например план до его утверждения, сохраняется читателем в файл под `.practice/`, который читает проверка. Текст, написанный моделью в примере, помечен как иллюстративный ("ваша формулировка будет отличаться").

Тела уроков Начального уровня не содержат номеров версий, цен или меток стабильности, и максимум одно предостережение, о безопасности. Уроки Среднего уровня содержат максимум два предостережения, а Продвинутого — максимум три.

Проверка `lesson-lint` обеспечивает эту форму для каждого урока (`docs/<level>/NN-*.md`) и Электива (`docs/<level>/electives/*.md`). Строка заголовка Электива говорит `Электив` вместо позиции, и его Проверка не имеет строки `npm run check`.

### Callouts

Callouts — это GitHub alerts, максимум два на урок, каждый с одним значением:

- `> [!NOTE]` для варианта или метки стабильности, процитированной слово в слово;
- `> [!WARNING]` для безопасности: секреты, разрешения, код, который выполняется с вашими правами;
- `> [!CAUTION]` для всего необратимого;
- `> [!TIP]` для необязательного сокращения.

`[!IMPORTANT]` не используется. Заметки о стоимости и подводные камни идут в слот Осторожно как обычные пункты. Никаких эмодзи в заголовках, маркерах списков, callouts или тексте урока. Цитируйте собственные символы интерфейса продукта внутри форматирования кода, например `⏸ plan mode on`.

### Диаграммы и изображения

- Диаграммы — Mermaid, со строками `accTitle:` и `accDescr:`. Предложение перед диаграммой формулирует её вывод словами.
- Состояние терминала, которое документация даёт как текст, показывается как текст в блоке кода, а не как скриншот.
- Снимок экрана разрешён только когда распознавание реального интерфейса является целью и текст не может это показать: максимум три на весь Начальный уровень. Каждый сделан в практическом шаблоне, обрезан до соответствующего интерфейса (без стартового баннера, без логотипа Anthropic), очищен от личных путей, имён пользователей, электронных писем аккаунтов, названий организаций и токенов, имеет рамку 1px и подпись `Claude Code vX.Y.Z (stable), YYYY-MM-DD`.
- README может также показывать до трёх снимков обучающего приложения практического шаблона, `npm run learn`, по тем же правилам. Их видимые подписи не содержат версии или даты, чтобы главная страница не датировала себя: строка `Claude Code vX.Y.Z (stable), YYYY-MM-DD` идёт в HTML-комментарии рядом с каждым изображением вместо этого.
- Каждое изображение имеет alt-текст, который говорит, что читатель должен извлечь из него, а не "скриншот" и не повторение подписи.
- Текст в диаграмме или изображении достигает контраста 4.5:1 в светлой и тёмной темах GitHub; другие метки достигают 3:1.
- Никаких сторонних изображений (логотипы, иконки, слайды, скриншоты продуктов), никакой анимации и встроенного видео. Есть два исключения. Маскот Claude, [`assets/brand/claude-jumping.svg`](https://raw.githubusercontent.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know/main/assets/brand/claude-jumping.svg) (MIT, указан в README), прыгает рядом с заголовком README и появляется на социальной карточке в своих цветах. Первый снимок обучающего приложения в README может быть одним анимированным GIF, кадры самого приложения, воспроизводимые по порядку (его маскот, Pip, приветствующий ученика), размером с неподвижный снимок, который он заменяет.
- Проверка `images` обеспечивает alt-текст, строки Mermaid, а также имена, ссылки и бюджет ниже.
- Новые изображения помещаются под `assets/`: `assets/brand/` для идентичности руководства, `assets/lessons/<lesson-id>/` для снимков и `assets/readme/` для README. Имена в kebab-case, пути явные и относительные. Бюджет: SVG до 50 КБ, снимок до 200 КБ, один анимированный GIF README до 1000 КБ. Каждое изображение, которое не является снимком, поставляется с редактируемым исходником рядом. Рисованный от руки SVG предназначен только для элементов идентичности руководства.

### Заголовки

- Заголовки не содержат дат, версий, названий моделей, слов "новый" или года, меток стабильности или эмодзи.
- Переименованный заголовок сохраняет свой старый slug как `<a id>` на строке выше ([Совместимость якорей](#anchor-compatibility)). Никаких дублирующихся id на странице и никакого синтаксиса `{#custom-id}`.

### Написание

**Делайте:**

- Начинайте с того, что читатель делает и что он видит.
- Используйте таблицу, когда строки сравнимы, но предпочитайте списки или сложенные блоки таблицам шире трёх коротких столбцов.
- Заканчивайте строку обратной косой чертой, где абзацу нужен перенос строки: файловое представление GitHub объединяет последовательные строки ([Переносы https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#line-breaks
- Используйте относительные ссылки `.md` и явные относительные пути к изображениям. Без front matter.
- Привязывайте утверждения, чувствительные к дате, к версии (`v2.1.x`) или полной дате.
- Оговаривайте и атрибутируйте сторонние оценки в предложении, которое их излагает.

**Не делайте:**

- Наполнитель, такой как "В этом разделе мы рассмотрим", "как мы упоминали ранее" или "стоит отметить, что". Вырезайте его.
- Маркетинговый язык. "Полное руководство по освоению..." звучит как хайп; начните с того, что читатель реально получает.
- Многоабзацные docstrings. Максимум одна короткая строка в примерах кода.
- Длинные тире в новой прозе. Оставляйте их только внутри цитат, идентификаторов и имён файлов. Проверка `em-dash` пропускает текст в обратных кавычках, блоках кода и двойных кавычках; любая другая строка, которая должна сохранить одно, несёт `<!-- allow-em-dash -->`.
- Утверждения о функциях, которые вы не проверили.

## Совместимость якорей

Перечисленные якоря и пути страниц из `main`, какими они были на момент начала переработки, продолжают разрешаться: [`.github/compat/anchors.txt`](https://github.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know/blob/main/.github/compat/anchors.txt) перечисляет якоря `README.md`, страниц `docs/` и `mcp-servers/README.md`, а [`.github/compat/paths.txt`](https://github.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know/blob/main/.github/compat/paths.txt) — пути страниц `docs/` и `mcp-servers/`, плюс Stub `specialized-agents/README.md`, который заменяет удалённую папку `specialized-agents/`, каждый из которых должен оставаться страницей или Stub. Только pull requests, которые добавляют Stubs, редактируют эти два списка.

Когда вы переименовываете или удаляете заголовок:

1. Добавьте невидимый HTML-якорь, который сохраняет старый slug:
   ```html
   <a id="old-slug-here"></a>
   ### Новый заголовок
   ```
2. Запустите [проверки](#checks). Правило `anchor-diff` завершается с ошибкой, называя каждый отсутствующий id, если якорь в `anchors.txt` или якорь на базовой ветке в `README.md` или `docs/` (страницы под `docs/legacy/` исключаются) больше не существует.

Когда вы перемещаете или удаляете страницу в `paths.txt`, оставьте Stub по старому пути: H1, строку, такую как `Эта страница переехала в [Hooks](../intermediate/05-hooks.md).` (или говорящую, что она была удалена в издании, с причиной в одно предложение и ссылкой на запись CHANGELOG), и якоря старой страницы как строки `<a id>`. Правило `stub-paths` завершается с ошибкой, если перечисленный путь отсутствует.

Это сохраняет работоспособность входящих ссылок из социальных постов даже после реструктуризации.

## Добавление навыка

Примеры для учащихся идут под `examples/<level>/<NN-lesson>/` (для Электива — под `examples/<level>/electives/<name>/`), в папке урока, который их использует. Каждая папка отражает структуру проекта, но ничто в ней не может находиться по пути, который Claude Code обнаруживает сам: используйте `dot-claude/` для `.claude/`, `dot-mcp.json` для `.mcp.json`, и `CLAUDE.example.md` и `AGENTS.example.md` для `CLAUDE.md` и `AGENTS.md`. Навык идёт в `dot-claude/skills/<name>/SKILL.md`, что означает "скопируйте в `.claude/skills/<name>/SKILL.md` в вашем проекте", где Claude Code загружает навыки проекта. Настоящая папка `.claude/` там не осталась бы инертной: Claude Code загружает навыки из вложенной `.claude/skills/`, как только Claude работает с файлами в этой папке ([Навыки](https://code.claude.com/docs/en/skills#where-skills-live)). Плагин хранит свой собственный `.claude-plugin/plugin.json`, потому что Claude Code не обнаруживает плагин под `examples/` сам: он не сканирует каталог `.claude/plugins/` проекта, и `examples/` не содержит `.claude/skills/` ([Справка по загрузке плагинов](https://code.claude.com/docs/en/plugins/loading#plugins-shared-through-a-repository)). Манифест marketplace идёт в `dot-claude-plugin/marketplace.json`, что означает "скопируйте в `.claude-plugin/marketplace.json`", так что ни папка примера, ни репозиторий руководства не могут быть добавлены как marketplace по пути папки или как `owner/repo` ([Справка по marketplace](https://code.claude.com/docs/en/plugins/marketplace-reference#marketplace-file)).

Каждый исполняемый пример (hook, скрипт, workflow, фрагмент настроек, навык с `allowed-tools`, плагин) соответствует этому контракту безопасности:

1. **Копировать для использования.** Он выполняется только после того, как Учащийся скопирует его в свой собственный проект.
2. **Только локально.** Никаких сетевых вызовов, сторонних API или ключей. Единственное исключение — сервер урока MCP, названный в этом уроке и установленный на закреплённой версии.
3. **Никакого захвата.** Ничто не копирует транскрипты и не логирует ввод или вывод инструментов. Пример, который должен логировать, держит лог ограниченным, в игнорируемой папке, и говорит об этом в своём заголовке.
4. **Минимальные привилегии.** Фрагмент настроек имеет узкие правила allow, никогда не `Write`, `Edit` или широкие записи `Bash(x:*)`, и правило deny `Read` для `.env`. Предоставляйте `allowed-tools` навыка экономно: Claude Code применяет `allowed-tools` навыка проекта даже в запуске `-p` в папке, которой вы никогда не доверяли ([Навыки](https://code.claude.com/docs/en/skills#pre-approve-tools-for-a-skill)).
5. **Блок заголовка.** Каждый файл и каждый README примера говорит, что он делает, когда выполняется (событие и matcher), его побочные эффекты, требования и платформы, как его выключить или удалить, и его строку теста: `Tested in Claude Code vX.Y.Z (stable) on <OS>, YYYY-MM-DD` или `Not yet tested in a session at this edition's version`.
6. **Платформа.** POSIX shell (macOS, Linux, WSL2). Зависимости ограничены bash, jq, стандартной библиотекой python3 и git, кроме сервера MCP из правила 2. Никаких `uv`, никаких pip-пакетов, никакой загрузки `.env`.
7. **Smoke test.** Он поставляет тест, который выполняется без Claude: hooks получают образец JSON, переданный через pipe, с проверкой кодов выхода и вывода; фрагменты настроек разбираются как JSON; навыки и агенты имеют валидный frontmatter.

Сообщайте о проблеме безопасности в примере, как описано в [SECURITY.md](SECURITY.md).

Корневая `.claude/` зарезервирована для инструментов мейнтейнеров. Не добавляйте туда навыки или другие примеры.
