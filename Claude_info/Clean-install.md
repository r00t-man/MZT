# 🧼 Чистая установка Claude Code на свой сервер (без ограничителей)

> Это «ванильная» версия — без `guard.sh`, без `settings.json` с урезанными `allow`/`deny`, без
> `setup-wizard.sh` и без привязки к инфраструктуре Remnawave/VPN. Claude Code ставится и работает
> ровно так, как задумано разработчиком «из коробки» — со стандартными разрешениями Anthropic.
>
> Если нужен вариант с жёсткими предохранителями для боевого VPN-сервера под root — смотри
> [основной README](./README.md) в этой же папке. Этот файл — для случаев, когда такая защита не
> нужна: тестовый/расходный сервер, личный проект, или когда хочешь сам настроить `permissions` под
> себя без готового хука.

---

## 🤔 Что это и зачем

**Claude Code** — агентный CLI-инструмент от Anthropic: работает в терминале, умеет сам читать и
редактировать файлы, запускать команды в shell, ходить в Docker/git и т.д. По сути — это тот же
Claude, но с доступом к твоему серверу через набор инструментов (tool use).

В этой «чистой» установке **нет** дополнительного слоя защиты поверх того, что даёт сам Claude Code
по умолчанию:

- ❌ нет `guard.sh` (жёсткого хука, который на уровне кода блокирует необратимые команды);
- ❌ нет заранее прописанного `deny`-списка под конкретную инфраструктуру;
- ❌ нет мастера настройки, который заводит SSH-ключи/API-ключи к внешним панелям.

Есть только штатное поведение Claude Code: **изменяющие действия (запись файлов, выполнение
команд) по умолчанию требуют твоего подтверждения** в терминале, а чтение файлов/поиск — нет,
потому что это безопасно и обратимо. Это разумная защита по умолчанию, но она держится на **твоём
внимании при каждом одобрении**, а не на детерминированном коде — в отличие от версии с `guard.sh`.

---

## ✅ Требования

- 🐧 Linux-сервер (Ubuntu/Debian и т.п. — подойдёт почти любой современный дистрибутив).
- 💳 Подписка **Claude Pro / Max** (или Team/Enterprise/Console-биллинг). На бесплатном плане
  Claude Code недоступен.
- 🖥️ SSH-доступ к серверу с любого клиента.
- (опционально) **Node.js**, если позже захочешь подключать MCP-серверы через `npx` — для базовой
  работы не нужен.

---

## 📦 Шаг 1. Установка

Нативный инсталлер ставит самодостаточный бинарник — Node.js для самого Claude Code не требуется:

```bash
curl -fsSL https://claude.ai/install.sh | bash
claude --version      # проверяем, что установилось
claude doctor         # самодиагностика: путь до бинарника, права, конфиги
```

`claude doctor` полезен, если что-то пошло не так после установки — покажет, чего не хватает.

---

## 🔑 Шаг 2. Авторизация

На сервере обычно нет браузера, поэтому используется режим **«открой ссылку на своём
компьютере → вставь код обратно в терминал сервера»**. Проброс портов не нужен.

```bash
cd ~            # или в любую рабочую папку — куда встанешь, там и будет работать агент
claude          # при первом запуске начнётся вход
```

1. Claude напечатает ссылку для входа в терминале.
2. Открой её в браузере на своём компьютере/телефоне → войди в аккаунт Claude.ai.
3. Браузер покажет код авторизации (обратной связи с сервером по SSH у него нет — это нормально).
4. Вставь код в терминал сервера.
5. Токен сохранится в `~/.claude` — повторный логин не потребуется.

> 🚫 **Важно:** не выставляй переменную `ANTHROPIC_API_KEY` на сервере, если хочешь списывать
> использование с подписки Pro/Max, а не с API-кредитов — они разные источники биллинга. Проверить,
> что используется, можно командой `/status` внутри Claude Code.

<details>
<summary>🆘 Если код-пейст не работает — запасной вариант через <code>setup-token</code></summary>

```bash
# на машине с браузером (например, на своём ноутбуке):
claude setup-token        # пройдёт OAuth и напечатает долгоживущий токен (нужен план Pro/Max)
```
```bash
# на сервере:
export CLAUDE_CODE_OAUTH_TOKEN="<токен_с_ноута>"
unset ANTHROPIC_API_KEY   # убедиться, что ключ не перебивает подписку
```
</details>

## 🚀 Шаг 3. Запуск

```bash
cd ~            # рабочая папка — Claude Code видит файлы относительно неё
claude          # запуск интерактивной сессии
```

Рабочая папка — не обязательно `/opt`, как в защищённой версии. Это может быть домашняя папка,
папка конкретного проекта или что угодно ещё: агент по умолчанию работает в пределах текущей
директории (плюс то, что ты сам разрешишь).

### Как это ведёт себя по умолчанию

Без своего `settings.json` Claude Code использует встроенные разумные настройки:

- 👀 **Чтение и поиск** (`Read`, `Glob`, `Grep`, просмотр файлов) — выполняются сразу, без вопросов,
  потому что не меняют состояние системы.
- ✋ **Изменяющие действия** (запись/правка файлов, выполнение shell-команд) — перед каждым таким
  действием Claude Code покажет, что именно собирается сделать, и спросит `Yes`/`No`.
- 🧠 Если один раз разрешить какую-то команду с опцией «не спрашивать больше в этой сессии» —
  дальше в рамках той же сессии она будет выполняться без повторного вопроса.

Это и есть вся защита в чистой установке: **человек на клавиатуре, читающий, что именно
подтверждает**. Нет отдельного кода, который бы вырезал заведомо опасные команды (`rm -rf`,
изменение firewall, снос Docker-томов и т.п.) — Claude Code их тоже покажет на подтверждение как
обычные изменяющие команды, но ничего не заблокирует автоматически.

## ⚙️ Опционально: свой `settings.json`

Если хочешь донастроить разрешения под себя — без хука и без готового чужого списка — создай
`~/.claude/settings.json`:

```json
{
  "permissions": {
    "defaultMode": "default",
    "allow": [
      "Read", "Glob", "Grep",
      "Bash(git status)", "Bash(git log:*)", "Bash(git diff:*)"
    ]
  }
}
```

- `defaultMode: "default"` — режим «спрашивать на всё неперечисленное» (штатное поведение).
- `allow` — список того, что можно расширить под свои привычные безопасные команды (по аналогии,
  что и как писать паттерны — см. `settings.json` в [защищённой версии](./settings.json), просто без
  `deny` и без хука).

Файл полностью опционален — без него Claude Code и так работает по встроенным умолчаниям.

## 📖 Опционально: `CLAUDE.md`

`CLAUDE.md` в рабочей папке — это «память» проекта: Claude Code читает его автоматически при
старте и держит в контексте. Полезно, если хочешь, чтобы агент помнил структуру проекта, стиль
кода, что не трогать и т.д., без необходимости объяснять это заново в каждой сессии.

Минимальный пример:

```markdown
# О проекте

Здесь работает [краткое описание: сайт/бот/сервис/сервер].

## Что важно знать
- стек: ...
- где лежит что: ...
- что нельзя менять без явного запроса: ...

## Как работать
- сначала диагностика, потом изменения
- перед деструктивными командами — уточнять
```

Сгенерировать черновик автоматически можно командой `/init` прямо внутри сессии Claude Code —
она просканирует текущую папку и предложит структуру.

## 🎛️ Режимы прав (переключение `Shift+Tab`)

Внутри сессии клавиша `Shift+Tab` циклически переключает режим работы:

| Режим | Что делает |
|-------|-----------|
| 🟡 **default** | Спрашивает подтверждение на каждое изменяющее действие (штатный режим) |
| 🟢 **acceptEdits** | Правки файлов принимаются автоматически, команды в shell — всё ещё спрашивают |
| 🔵 **plan mode** | Только чтение и составление плана — ничего не меняет, удобно для диагностики/ревью |
| 🔴 **bypassPermissions** (`--dangerously-skip-permissions`) | Вообще ничего не спрашивает — **не использовать на сервере с реальными данными** |

> ⚠️ Флаг `--dangerously-skip-permissions` снимает вообще все подтверждения. В чистой установке
> это означает полное отсутствие какого-либо контроля над действиями агента — используй только в
> одноразовой песочнице, которую не жалко потерять.

## 🧵 Работа в консоли

| Команда | Что делает |
|---------|-----------|
| `/help` | список всех команд |
| `/model sonnet` | выбрать модель (Sonnet — оптимальный баланс на Pro) |
| `/status` | проверить аккаунт и источник биллинга (подписка vs API) |
| `/permissions` | посмотреть/поправить правила allow-deny |
| `/cost` | потраченные токены/стоимость за сессию |
| `/clear` | очистить контекст |
| `/compact` | ужать историю диалога, сохранив суть |
| `/init` | сгенерировать `CLAUDE.md` по текущему проекту |
| `/exit` | выйти |

Чтобы не терять сессию при обрыве SSH — запускай в `tmux`:

```bash
tmux new -s claude
claude
# отцепиться: Ctrl+B, затем D
tmux attach -t claude   # вернуться позже
```

Продолжить прошлый разговор: `claude --continue` (последний) или `claude --resume` (выбор из списка).

## 💸 Лимиты подписки Pro/Max

- Интерактивные сессии в терминале едят тот же лимит, что и обычный чат на claude.ai (5-часовое и
  недельное окно).
- Неинтерактивный режим (`claude -p "..."`, cron-задачи, Agent SDK) расходует отдельный, гораздо
  меньший месячный лимит — для регулярных автопрогонов по расписанию его обычно не хватает, там
  разумнее отдельный API-ключ из Console именно под cron, оставив интерактив на подписке.

## 🛟 Быстрый траблшутинг

| Симптом | Причина / решение |
|---------|-------------------|
| Логин просит браузер и зависает | Используй код-пейст (Шаг 2) или `setup-token` с другой машины |
| `/status` показывает API-биллинг вместо подписки | `unset ANTHROPIC_API_KEY` |
| Логин не резолвится/виснет без ошибки | DNS блокирует `claude.ai`/`auth.anthropic.com` — попробуй сменить DNS (например 1.1.1.1) |
| Сессия обрывается при разрыве SSH | Запускай в `tmux` |

## ⚠️ Дисклеймер

В этой установке **нет** отдельного детерминированного предохранителя — вся защита держится на
том, что ты сам читаешь, что именно подтверждаешь на каждый запрос `Yes`/`No`. Для сервера с
реальными данными/деньгами/продовой инфраструктурой рекомендуется версия с `guard.sh` из
[основного README](./README.md), либо самостоятельно написанный аналог под свою специфику.
