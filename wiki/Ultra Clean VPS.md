# 🧹 Ultra Clean VPS v3 (Ubuntu 24.04)

Скрипт для **глубокой очистки VPS на Ubuntu 24.04**.

Подходит для серверов:

* 💾 с маленьким диском (10–20GB)
* 🐳 Docker серверов
* 🌐 серверов с nginx (VPN-ноды, прокси, reverse proxy)
* ⚡ VPS после долгой работы
* 🚀 новых серверов перед развёртыванием сервисов

Скрипт удаляет и чистит: ненужные пакеты и кеши APT, старые ядра, journald-логи, **nginx-логи** (сразу
+ ротация на будущее), snap и firmware, лишние локали, Docker-мусор и раздувшиеся логи контейнеров.

Это позволяет **освободить от 1GB до 8GB места на диске**.

> [!NOTE]
> **v3 vs v2:** добавлена очистка nginx-логов (шаги 5–6) и усечение логов Docker-контейнеров (шаг 8).
> На нагруженных нодах nginx может накапливать **1+ GB логов за сутки** — теперь это не проблема.

## ⚡ Быстрая установка (одной командой)

```bash
curl -fsSL https://raw.githubusercontent.com/r00t-man/MZT/refs/heads/main/files/Ultra_Clean_VPS.sh | sudo bash
```

Скрипт автоматически выполнит очистку и выведет отчёт до/после.

### 💾 Бэкап перед очисткой (рекомендуется)

Если на диске есть запас места, перед запуском можно сохранить удаляемые данные в архив:

```bash
sudo bash -c 'command -v tar >/dev/null || (apt update && apt install -y tar); TS=$(date +%F_%H-%M-%S); mkdir -p /backup_ultra_clean; tar -czf /backup_ultra_clean/ultra_clean_backup_${TS}.tar.gz /var/log/journal /var/lib/apt/lists /var/cache/apt/archives /tmp /var/tmp /var/lib/docker 2>/dev/null || true; ls -lh /backup_ultra_clean'
```

Создаёт `/backup_ultra_clean`, собирает архив с датой/временем в имени, показывает итоговый размер.

> [!NOTE]
> Если Docker не установлен или часть путей отсутствует — это нормально, команда продолжит работу.

### 📥 Скачать и запустить вручную

```bash
wget https://raw.githubusercontent.com/r00t-man/MZT/refs/heads/main/files/Ultra_Clean_VPS.sh
chmod +x Ultra_Clean_VPS.sh
sudo ./Ultra_Clean_VPS.sh
```

## 🎯 Что делает скрипт

### 1️⃣ Очистка APT

Удаляются кеш пакетов, ненужные зависимости, остатки удалённых пакетов (`rc` в dpkg).

### 2️⃣ Очистка системных логов (Journald)

Linux хранит логи в `/var/log/journal` — со временем сотни мегабайт или гигабайты. Скрипт
устанавливает постоянные лимиты через `/etc/systemd/journald.conf.d/limits.conf`:

```ini
[Journal]
SystemMaxUse=100M
SystemKeepFree=500M
MaxRetentionSec=7day
```

Настройки сохраняются после перезагрузки.

### 3️⃣ Пересборка APT-индексов

Удаляются старые списки пакетов (`/var/lib/apt/lists`), затем выполняется `apt update` — чистый
актуальный индекс.

### 4️⃣ Архивные логи /var/log

Удаляются архивные и ротированные файлы **крупнее 50MB** (`*.log.1`, `*.log.2`, `*.gz`...). Активные
`.log` файлы **не трогаются**.

### 5️⃣ Nginx: немедленная очистка логов 🆕

На нагруженных серверах nginx-логи могут накапливаться очень быстро. Реальный пример — нода с
VPN-трафиком за сутки:

```
cloud_access.log.1   →  1.1 GB
data_access.log.3.gz →  61 MB
```

Итого: **1.2 GB только в /var/log/nginx**. Скрипт немедленно чистит все `*.gz` файлы, ротированные
`.log.2`/`.log.3`+ и `.log.1` файлы **крупнее 100MB**. Активные `.log` файлы **не трогаются**.

После очистки скрипт показывает что осталось:

```
До:    1.2G
После: 44M
  44M  data_access.log
 2.8M  data_error.log
```

### 6️⃣ Nginx: настройка ротации на будущее 🆕

Скрипт обновляет `/etc/logrotate.d/nginx`:

```
daily          — ротация раз в сутки
size 100M      — или при достижении 100MB (что наступит раньше)
rotate 2       — хранить 2 ротации
compress       — сжимать старые
delaycompress  — .log.1 не сжимать (nginx перезапишет)
```

Итого максимум в `/var/log/nginx`: `≈ активный лог + 1 архив × сжатый = ~150-200MB` вместо нескольких
гигабайт.

> [!NOTE]
> Если nginx не установлен — шаг пропускается.

### 7️⃣ Docker: безопасная очистка

Удаляются dangling images, stopped containers, unused networks, build cache. **Образы запущенных
контейнеров не трогаются** — `docker system prune` без флага `-a`. Скрипт показывает `docker system df`
до и после.

### 8️⃣ Docker: лимиты логов + очистка существующих

По умолчанию Docker пишет **бесконечные json-логи** в `/var/lib/docker/containers/<id>/*-json.log`.
Скрипт устанавливает постоянные лимиты:

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

Теперь один контейнер — максимум **≈30MB логов**. Если у запущенных контейнеров `*-json.log` больше
100MB — файл усекается до 0 без остановки контейнера:

```
✔ Усечён лог контейнера: remnawave-node (312MB → 0)
```

Контейнер продолжает работать, логи пишутся заново.

### 9️⃣ Удаление документации

Удаляются `/usr/share/doc`, `/usr/share/man` — на VPS они почти никогда не используются. Экономия:
**100–300MB**.

### 🔟 Удаление Snap

Ubuntu устанавливает `snapd` по умолчанию, но на большинстве VPS он не используется, занимает
200–400MB и создаёт loop-устройства. Скрипт полностью удаляет snap, snapd и кеш.

### 1️⃣1️⃣ Очистка локалей

Linux хранит локали для десятков языков — это 200–500MB. Скрипт оставляет только `en_US.UTF-8`,
`en_GB.UTF-8`, `ru_RU.UTF-8`.

### 1️⃣2️⃣ Удаление firmware

Пакет `linux-firmware` занимает 300–600MB. На VPS не нужен — виртуальное железо не требует реальных
драйверов устройств.

> [!WARNING]
> На **bare-metal серверах** не удалять.

### 1️⃣3️⃣ Очистка старых ядер

Ubuntu хранит несколько версий ядра. Скрипт оставляет **текущее** (`uname -r`) и **последнее** по
версии, остальные удаляются — безопасная практика.

### 1️⃣4️⃣ Очистка временных файлов

`/tmp`, `/var/tmp`.

## 📊 Финальный отчёт

После завершения скрипт выводит сравнение до и после:

```
  Диск ДО:    4.2G / 20G (avail: 14G)
  Диск ПОСЛЕ: 1.8G / 20G (avail: 17G)
```

А также топ-15 директорий по размеру (`du -xh`), `docker system df`, список запущенных контейнеров.

| Тип сервера | Освобождается |
|-------------|---------------|
| маленький VPS | 1–3 GB |
| Docker сервер | 2–6 GB |
| VPN-нода с nginx | **3–9 GB** |
| старый сервер | до 8 GB |

## 🧠 Когда использовать

После установки нового сервера, если диск почти заполнен, на нодах где nginx активно логирует
трафик, раз в несколько месяцев для профилактики.

---

> [!IMPORTANT]
> Рассчитан на **VPS и облачные серверы**. Шаг удаления firmware — **не применять на bare-metal**.
> Docker-образы запущенных контейнеров **не удаляются**. Активные `.log` файлы nginx **не трогаются**,
> только ротированные.
